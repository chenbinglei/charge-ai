# 充电运营平台功能详细说明 V4.0

**需求基线**：2026.08-V4.0  
**状态**：内部评审稿  
**关联文档**：[菜单架构](充电运营平台菜单架构-v4.0.md)｜[业务规则基线](充电运营平台业务规则基线-v4.0.md)｜[场景与流程图集](充电运营平台场景与流程图集-v4.0.md)

## 1. 使用方法

本文件以菜单编号为主键补充页面的功能目的、适用角色、主要操作、输入输出和异常闭环。页面原型、字段字典、接口和验收用例必须继续引用同一菜单编号与规则编号。

| 字段 | 含义 |
| --- | --- |
| 功能目的 | 该页面解决的业务问题。 |
| 使用角色 | 可以进入页面的角色；实际页面/数据范围仍按 IOT 或 P1 授权。 |
| 主要操作 | 页面必须支持的核心动作，不列样式性操作。 |
| 输入与输出 | 关键业务输入、结果、事件或报表。 |
| 异常闭环 | 失败、冲突、超限或需人工处理时的归属页面。 |

## 2. P1 运营管理平台

| 菜单编号 | 功能目的与使用角色 | 主要操作 | 输入与输出 | 异常闭环 |
| --- | --- | --- | --- | --- |
| P1-WB-01~05 | 平台超级管理员、租户运营人员掌握经营与待办；大屏配置人员发布 D1。 | 指标筛选、待办分派、配置草稿/发布/回滚。 | 租户/站点范围、指标字典、发布版本。 | 指标延迟、无数据、发布失败进入运营待办与发布记录。 |
| P1-ASSET-01~07 | 场站运营、资产人员维护运营资料和业务能力；不承担 IOT 接入。 | 维护场站展示、启用 VIN/金额启动业务策略、停车/门禁/闸机规则。 | IOT 资产与能力同步、场站服务事件。 | IOT 能力与 P1 启用策略不一致时禁止开放相应启动方式并生成待办。 |
| P1-ORD-01~05 | 客服、运营、财务处理个人/企业/屏幕订单及异常。 | 查询、导出、退款申请、订单修复、VIN 复核、人工结算。 | 订单、价格、资金、VIN、设备回执、监管状态快照。 | 未核 VIN、强制启动、资金不足进入异常/未结算队列，禁止静默改单。 |
| P1-CUST-01~02 | 客服和运营管理个人用户；会员不是用户主档前提。 | 查询车主、车辆、车型、认证、隐私申请与用户分组。 | 微信手机号主体、订单、车辆、隐私同意。 | 注销、数据导出、车辆认证失败进入数据权利/认证处理流程。 |
| P1-CUST-03~08 | 企业运营人员建立企业、组织、车队、车辆、VIN、企业账号和企业端授权。 | 创建/邀请/停用账号，维护车队和唯一 VIN 归属，设置企业策略与企业端角色。 | 企业、组织、车队、车辆、成员关系、授权版本。 | VIN 重复、车辆跨车队、离职账号、授权同步失败均需阻断并留审计。 |
| P1-CUST-09~10 | 平台运营人员管理运营商/租户业务资料、M3 授权和合作伙伴。 | 同步租户、配置 M3 页面/站点范围、合作伙伴合同与用户互访授权。 | IOT 租户主档、伙伴关系、授权范围。 | IOT 资产范围不满足 M3 授权时，页面只读告警，不可越权执行。 |
| P1-MKT-01~04 | 营销人员维护可选会员、权益、活动和触达。 | 会员权益配置、券红包积分发放/核销、活动预算、消息发送和反馈处理。 | 用户分群、权益库存、活动预算、核销流水。 | 库存不足、规则冲突、退款返还、发送失败均形成流水和重试/人工处理。 |
| P1-PRICE-01~03 | 价格管理员定义应收规则，财务只消费结果。 | 创建版本、设备/场站应用、定时生效、回滚、企业协议价。 | 分时价格、服务费、停车/占位规则、版本快照。 | 生效时间冲突、设备分组无效、历史订单禁止重算。 |
| P1-FIN-01 | 财务管理员管理多渠道、多商户和支付路由。 | 配置适用租户/场站/应用、启停渠道、账单导入与渠道状态查看。 | 支付路由、商户密钥引用、回调/对账结果。 | 回调重复、商户不可用、路由无匹配进入支付异常队列。 |
| P1-FIN-02~06 | 财务、企业资金人员管理个人/企业/车队/电卡资金、对账和发票。 | 充值、退款、冻结、资金划拨、卡挂失、对账、开票与红冲。 | 各级余额、冻结、授信、流水、账单、发票。 | 余额不足、重复冻结、双重占用、对账差异、人工结算均有审批和审计。 |
| P1-FIN-07 | 合作伙伴结算人员处理分润。 | 维护规则、生成账单、确认、结算和对账。 | 场站/订单归属、分润比例、结算单。 | 订单调整后重算、结算争议、账单锁定和冲正。 |
| P1-OPS-01~04 | 运维人员处理 IOT 同步告警、工单、费用异常和受控操作。 | 告警确认、派单、巡检、远程启动/停止/重启、工单验收。 | 告警、工单、设备能力、IOT 指令回执。 | 远程操作须双重鉴权；回执超时、操作失败、工单 SLA 超时进入待办。 |
| P1-DATA-01~04 | 运营、财务、企业和设备人员获得多维分析与导出。 | 按租户/站点/企业/车辆/卡筛选、订阅、导出。 | 聚合指标、报表文件、导出审计。 | 超范围导出、指标口径变更、异步导出失败均留痕。 |
| P1-REG-01~03 | 合规人员管理省市监管业务并追踪可靠上报。 | 监管档案、映射启用、任务检索、补推审批、差异关闭。 | 上报任务、回执、差异单和审计。 | 自动重试耗尽、漏推、回执不一致进入合规待办。 |
| P1-SET-01~04 | 平台配置人员管理应用内容、业务参数、安全审计和服务包。 | 小程序发布、协议版本、业务参数、审批流、导出审计、应用开通。 | 应用版本、业务参数、审批记录、IOT 授权同步状态。 | 不在 P1 创建 IOT 运营角色；同步失败仅告警和跳转 IOT 处理。 |

## 3. P2 企业客户管理平台

| 菜单编号 | 功能目的与使用角色 | 主要操作 | 输入与输出 | 异常闭环 |
| --- | --- | --- | --- | --- |
| P2-WB-01 | 企业管理员、财务、车队与运维负责人查看企业经营。 | 查看余额、授信、订单、异常、告警和待办。 | 企业范围汇总。 | 余额、VIN、账单和运维异常跳转相应工作区。 |
| P2-CFG-01~04 | 企业管理员配置企业业务资料、车队、车辆与电卡。 | 维护组织/成本中心、车队、VIN、卡授权、挂失换卡。 | 企业主数据、车队/车辆/卡关系。 | 车辆重复、跨车队、未结算订单、卡冻结时禁止变更。 |
| P2-FIN-01~03 | 企业资金人员管理资金和无 VIN 先充后付策略。 | 企业充值、查看授信、车队资金划拨、设置限额和策略。 | 余额、冻结、授信、策略版本。 | 调额、授信开关、异常订单结算遵循经办—复核—执行。 |
| P2-ORD-01 / P2-BILL-01 | 企业管理员和财务追踪订单、账单、VIN 异常和票据。 | 查询、确认差异、申请开票、下载账单。 | 订单、车队归集、资金流水、发票。 | 无 VIN/不匹配、未结算、账单差异进入企业异常队列。 |
| P2-OPS-01 / P2-DATA-01 | 企业运维和管理人员查看授权资产并做分析。 | 监控、提交工单、验收、报表导出。 | 授权站点设备、告警、工单与企业报表。 | 设备动作同时校验企业业务权限和 IOT 资产范围。 |
| P2-SET-01 | 企业用户查看其已获授权。 | 查看角色、页面和数据范围。 | P1 下发的授权版本。 | 无权限或版本过期时重新登录/联系企业管理员。 |

## 4. 小程序和独立大屏

| 终端 | 菜单编号 | 功能目的与使用角色 | 主要操作 | 异常闭环 |
| --- | --- | --- | --- | --- |
| M1 | M1-HOME-01~03 | 个人用户找站并完成公共充电。 | 找站、扫码、外部预付/余额/权益支付、停止、结算。 | 未绑定车辆不阻断；余额/预付失败不启动；订单异常进入订单详情/客服。 |
| M1 | M1-ORD-01 / M1-ME-01~02 | 个人用户管理订单、发票、车辆、余额和隐私。 | 申请发票、查退款、充值、查看权益、联系客服。 | 发票主体拆分、退款失败、注销前余额/订单校验。 |
| M2 | M2-HOME-01~02 | 企业员工/司机使用企业资金或电卡充电。 | 扫码、接受 VIN/资金校验、按固定金额启动、电卡使用。 | 不允许个人支付；资金/限额不足拒绝启动；无 VIN 仅在企业策略允许时走先充后付。 |
| M2 | M2-ORD-01 / M2-ME-01 | 企业用户查看本人企业订单与身份。 | 查看 VIN、车队、资金、异常状态和可用站点。 | VIN 后补不匹配标记异常；司机默认不可查看企业全量资金。 |
| M3 | M3-HOME-01~M3-ME-01 | 运营商/租户现场人员完成移动经营和现场运营。 | 看板、巡检、告警确认、工单、异常提交、订单查询。 | 高风险设备控制需 P1 动作权限 ∩ IOT 站点设备范围；资金配置留在 P1。 |
| M4 | M4-HOME-01~M4-ME-01 | 企业管理员移动查看、待办审批和现场运维。 | 查询企业数据、审批待办、告警工单和现场验收。 | 不提供扫码/启动；余额调账、卡划拨、授信开关、权限变更回 P2/P1。 |
| D1 | D1-OV-01~D1-TOPIC-01 | 指挥中心展示已发布运营专题。 | 自动刷新、轮播、专题切换。 | 数据范围仅按 P1 发布版本；配置或数据异常回 P1 处理。 |

## 5. 原型与验收的最小补充要求

每个菜单编号在进入原型前必须补齐：页面字段清单、权限动作清单、接口/事件、状态机、至少一条正常和一条异常验收用例。复杂资金、设备控制、监管和审批页面必须补齐操作日志与导出审计要求。
