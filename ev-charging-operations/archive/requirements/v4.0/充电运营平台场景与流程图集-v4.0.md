## 1. 使用说明

本图集只描述当前菜单架构已经承载的业务闭环。流程中的规则编号以《业务规则基线》为准；页面与角色说明以《功能详细说明》为准。V2G 不属于当前版本菜单与流程，后续可行性结论见《下一阶段优化清单》。

## 2. 总体应用与职责架构

```mermaid
flowchart TB
  IOT["IOT 平台\n多租户、站点/设备/枪、协议接入、遥测、设备权限"]
  P1["运营管理平台\n运营、客户企业、资金、订单、营销、监管"]
  P2["企业客户管理平台\n企业组织、车队、车辆、账户、报表"]
  M1["个人充电小程序\n找站、扫码、预付、订单、发票"]
  M2["企业充电小程序\n企业账号、扫码、VIN/电卡充电、订单"]
  M3["运营商小程序\n站点现场运营与运维"]
  M4["企业客户小程序\n企业数据、配置、现场运维\n不提供充电"]
  D1["运营大屏独立应用\n只读展示"]
  PAY["支付渠道\n微信/支付宝/银联/第三方"]
  REG["省市监管平台\n入网、订单、状态、补推与对账"]
  EXT["停车/门禁/闸机等业务协同"]

  IOT -->|"租户、资产、能力、遥测、设备权限"| P1
  P1 --> P2
  P1 --> M1
  P1 --> M2
  P1 --> M3
  P1 --> M4
  P1 --> D1
  P1 <--> PAY
  P1 <--> REG
  P1 <--> EXT
  IOT -->|"启停、金额下发、订单/告警上报"| P1
```

边界：IOT 平台负责设备协议、设备接入与设备权限；运营管理平台不配置 IOT 接口/API。企业客户子系统的用户、角色、页面与数据范围由运营管理平台管理。运营大屏为独立应用，展示项由运营管理平台配置并发布。

## 2.1 权限与敏感操作审批

适用：运营管理平台 Web、场站商家小程序、企业客户子系统。关联：P1-SET-03、P1-CUST-06、R-AUTH-01～06。

```mermaid
flowchart LR
  U["用户发起访问或操作"] --> I["IOT 权限判定\n租户、页面、数据范围"]
  I -- "无权限" --> X["拒绝并记录"]
  I -- "有权限" --> A{"是否敏感业务动作？\n退款、人工结算、资金划拨等"}
  A -- "否" --> B["执行业务操作"]
  A -- "是" --> P["P1 业务审批与职责分离"]
  P -- "拒绝/超时" --> Y["终止并记录审批结果"]
  P -- "通过" --> C{"是否设备控制？"}
  C -- "否" --> B
  C -- "是" --> D["再次校验 IOT 资产范围\n与设备实时能力"]
  D -- "不满足" --> Z["拒绝下发并生成异常记录"]
  D -- "满足" --> B
```

说明：IOT 是运营端 Web 页面与数据权限的唯一来源；P1 的审批只约束高风险业务动作，不能替代或绕过 IOT 权限。P1 管理的是企业客户子系统及场站商家小程序的业务账号、角色、页面和数据范围。

## 3. 个人用户扫码预付充电

适用：公共站个人用户，不要求预先绑定或认证车辆。关联：P1-ORD-01、M1-CHG-01、R-PERSON-01～04、R-START-01。

```mermaid
flowchart TD
  A["个人用户扫码识别枪"] --> B{"枪可启动且站点可服务？"}
  B -- 否 --> X["提示不可用原因并记录"]
  B -- 是 --> C["选择支付方式\n余额 / 微信 / 支付宝 / 银联 / 第三方"]
  C --> D{"余额足够或外部预付成功？"}
  D -- 否 --> Y["提示支付失败或余额不足"]
  D -- 是 --> E["冻结余额或确认预付"]
  E --> F["向 IOT 下发带金额的启动指令"]
  F --> G{"设备确认启动？"}
  G -- 否 --> H["释放冻结或发起原路退款\n记录启动失败"]
  G -- 是 --> I["充电中：状态、费用与告警展示"]
  I --> J["结束订单上报"]
  J --> K["按规则结算、扣款/退款、生成订单"]
```

## 4. 企业小程序：VIN 匹配车队的扫码充电

适用：企业员工/司机使用企业账号扫码；设备已配置“可获取 VIN”，插枪后上报 VIN。关联：M2-CHG-01、P1-CUST-05、P1-FIN-04、R-FLEET-01～04、R-START-02、R-ORDER-02。

```mermaid
flowchart TD
  A["企业用户扫码、插枪"] --> B["IOT 上报枪状态与 VIN"]
  B --> C{"VIN 是否属于站点可服务企业\n任一车队的已启用车辆？"}
  C -- 否 --> X["拒绝启动\n提示联系企业管理员/运维维护车辆"]
  C -- 是 --> D["定位车辆所属唯一车队"]
  D --> E{"车队场站范围、周期/金额限制\n及可用预存余额满足？"}
  E -- 否 --> Y["拒绝启动并记录校验原因"]
  E -- 是 --> F["按车队固定单笔启动金额冻结资金"]
  F --> G["下发金额启动指令"]
  G --> H{"设备确认启动？"}
  H -- 否 --> I["解冻并记录失败"]
  H -- 是 --> J["订单结束：按实际金额扣车队资金"]
  J --> K["回写车队、车辆、VIN 与核验快照"]
```

## 5. 企业小程序：设备未获取 VIN 的先充后付

适用：仅限企业开启先充后付，且设备“不可获取 VIN”或本次未取得 VIN 的企业小程序扫码场景。关联：P1-CUST-04、P1-CUST-05、R-FUND-04～06、R-START-03、R-ORDER-03。

```mermaid
flowchart TD
  A["企业用户扫码、插枪"] --> B{"取得可核验 VIN？"}
  B -- 是 --> C["转入 VIN 匹配车队流程"]
  B -- 否 --> D{"企业是否启用先充后付？"}
  D -- 否 --> X["拒绝启动"]
  D -- 是 --> E{"企业可用预存余额 + 可用授信\n是否不少于企业默认单笔额度？"}
  E -- 否 --> Y["拒绝启动并提示联系企业充值"]
  E -- 是 --> F["以企业默认单笔额度下发启动"]
  F --> G["订单结束上报"]
  G --> H["先扣企业预存余额\n不足部分占用授信"]
  H --> I["标记 VIN 异常 / 待归属\n保留用户、站点、枪、订单快照"]
```

说明：后续若订单补报 VIN 并与该企业车队车辆匹配，可由授权人员完成归属修正；资金流水不得覆盖重写，必须保留调整流水与审计记录。

## 6. 企业电卡与屏幕刷卡启动

适用：企业电卡刷卡，或企业用户在 M2 绑定电卡后以电卡方式启动。关联：P1-FIN-05、M2-CARD-01、R-CARD-01～05、R-START-04。

```mermaid
flowchart TD
  A["刷企业电卡 / M2 选择已绑定电卡"] --> B{"卡状态正常、绑定关系有效？"}
  B -- 否 --> X["拒绝启动"]
  B -- 是 --> C{"卡所属车队的场站、周期限制通过\n卡可用余额与企业资金状态充足？"}
  C -- 否 --> Y["拒绝启动，记录原因"]
  C -- 是 --> D["按电卡单笔启动金额冻结卡余额"]
  D --> E["下发金额启动指令"]
  E --> F["订单结束，按实际费用扣卡余额"]
  F --> G["同步车队与企业资金占用/流水"]
```

## 7. 设备屏幕 VIN 鉴权与强制启动

适用：具备屏幕 VIN 输入/读取或强制启动能力的设备。关联：P1-ASSET-02、P1-ORD-03、R-ASSET-03、R-START-05～06、R-ORDER-04。

```mermaid
flowchart TD
  A["设备屏幕发起启动"] --> B{"启动方式"}
  B -- "VIN 鉴权" --> C{"VIN 属于本站可服务企业\n任一已启用车队？"}
  C -- 否 --> D["鉴权失败，设备不启动"]
  C -- 是 --> E["按所属车队固定金额冻结并启动"]
  B -- "强制启动" --> F["设备直接启动，仅接收订单上报"]
  F --> G{"结束订单的 VIN 能匹配\n本站服务企业车辆？"}
  G -- 是 --> H["按匹配企业资金结算，记录强制启动来源"]
  G -- 否 --> I["异常充电订单：未结算\n待人工配置归属和结算"]
```

## 8. 企业资金分配、冻结与结算

适用：企业预存余额、车队资金、电卡余额与可选授信的资金一致性控制。关联：P1-FIN-04～05、P2-FIN-01～02、R-FUND-01～06、R-CARD-01～05。

```mermaid
flowchart LR
  A["企业总预存余额\n未分配可用资金"] -->|"划拨并锁定"| B["车队可用资金"]
  B -->|"划拨并锁定"| C["企业电卡独立余额"]
  B -->|"VIN 匹配启动冻结"| D["订单冻结"]
  C -->|"刷卡/绑卡启动冻结"| D
  D -->|"订单结束按实际金额"| E["结算扣款 / 释放差额"]
  A -. "仅无 VIN 企业小程序\n且启用先充后付" .-> F["企业可用授信"]
  F -->|"预存不足时占用"| E
```

资金原则：车队与电卡的“余额”均是企业总预存余额的已锁定子余额，不能重复可用；订单启动只冻结，不直接最终扣款；订单结束才按实际费用结算，释放未使用冻结金额。

## 9. 停车、门禁、闸机协同

适用：泰安等具有停车收费、充电减免、充电用户开门或出场抬杆需求的站点。关联：P1-ASSET-05、P1-PRICE-03、P1-ORD-04、R-SERVICE-01～03。

```mermaid
sequenceDiagram
  participant U as 用户/车辆
  participant P as 运营管理平台
  participant C as 充电订单
  participant X as 停车/门禁/闸机
  U->>C: 启动并完成充电
  C->>P: 上报订单、充电时长/电量
  P->>P: 按站点规则计算停车减免/门禁资格
  P->>X: 发送一次性授权或减免结果
  X-->>U: 开门/抬杆/停车费优惠
  X-->>P: 回传执行结果
  P->>P: 保存关联、失败重试与人工处理记录
```

## 10. 省市监管报送、补推与对账

适用：不同省市监管协议、入网参数及订单漏推治理。关联：P1-REG-01～04、R-REG-01～05。

```mermaid
flowchart TD
  A["站点/设备/订单状态变化"] --> B["生成监管报送事件 Outbox"]
  B --> C["按监管地区协议映射、签名、发送"]
  C --> D{"监管平台回执成功？"}
  D -- 是 --> E["保存回执与报送成功记录"]
  D -- 否 --> F["按策略重试并记录失败原因"]
  F --> G{"超过阈值或发现漏推？"}
  G -- 否 --> C
  G -- 是 --> H["异常池：筛选、人工补推、重放"]
  H --> I["监管对账与差异闭环"]
```
