## 2. 范围口径

1. IOT 平台管理多租户、站点/设备/枪接入、设备协议、设备能力、遥测、设备原始告警和运营管理平台 Web 用户的租户/页面/数据权限；运营平台不配置 IOT 接口/API。
2. 运营管理平台管理运营业务、企业客户子系统的用户/角色/页面/数据范围，以及场站商家（运营商）小程序的业务授权。
3. 企业客户管理平台负责企业管理员的 Web 管理；企业客户小程序仅做企业数据、配置和现场运维，不提供充电。企业员工/司机使用独立的企业充电小程序。
4. 车辆 VIN 只在车辆管理维护；订单保存 VIN 及核验快照，不把订单页作为车辆主数据维护入口。
5. V2G 不加入 V4.0 菜单、功能和业务流程；其调研结论与后续立项条件见《下一阶段优化清单》。

## 3. 版本控制规则

1. 同一评审轮的菜单、功能、规则、流程四类文件必须使用相同的“需求基线编号”和版本号；任一文件变更后，同步检查其关联文档。
2. 新增或调整菜单，必须同时更新：功能详细说明、关联规则编号、场景/流程和追踪矩阵（后续 N-02）。
3. 规则口径与流程冲突时，以业务规则基线为裁决依据；菜单仅表达入口与归属，不重复写完整规则。
4. 已替代版本移动至 [archive/requirements](../README.md) 对应分类，文件头标明归档日期、替代版本和不可作为当前实现依据。
5. 代码、原型、接口、测试用例和交付文档均须注明所实现的需求基线编号；输出路径遵循现役 [文档与代码输出归档规则](../../../docs/standards/文档与代码输出归档规则.md)。
