# 个人用户主档接口规范

> 版本：v1.0
> 状态：W2 模块实施前的强制接口设计基线；本文不是已发布运行时 API。
> 依据：[personal-identity-v1.yaml](../../contracts/openapi/personal-identity-v1.yaml) v1.0.0、《[API 通用接口规范](API通用接口规范-v1.md)》、《[W2 技术设计与契约包](../design/W2-IAM个人身份与配置技术设计与契约包.md)》。
> 边界：仅覆盖 M1 个人用户主档与渠道身份映射的管理侧接口；M1 个人用户业务资格、订单、钱包、权益不在本接口范围。M1 不提供自助绑定/解绑/账户合并。

## 1. 资源边界

- `personal_user` 是 M1 个人充电用户的主档实体：渠道身份（微信/支付宝）经指纹映射关联，不存外部主体原文于明文。
- L3 敏感字段（外部主体原文、手机号）加密存储；接口与日志只出现脱敏指纹（`*Masked` 字段），查询走指纹索引而非明文。
- 渠道登录触发的创建为幂等操作：同一渠道身份重复登录返回既有主档，不产生重复账号。
- 渠道身份冲突（同一外部主体映射到多个主档等）进入冲突案例表，由平台侧人工处置；M1 侧不做自动合并。

### 1.1 鉴权模型（资源 + 读/写两档）

- 本接口涉及的权限码：`personal_user:read`（列表/详情/冲突查询）、`personal_user:write`（资料编辑、冲突处置）。
- 鉴权规则：`GET` 校验 `resource:read`；`POST`/`PUT`/`PATCH` 校验 `resource:write`；权限不足返回 `FORBIDDEN`(403)。

## 2. 统一资源接口

| 方法与路径 | 权限码 | 请求模型 | 响应模型 | 中文语义与约束 |
| --- | --- | --- | --- | --- |
| `GET /api/v1/personal-users` | `personal_user:read` | `status`/`channelType`/`source`/分页 | `ApiResponse<PageResponse<PersonalUserListVO>>` | 按状态、渠道、来源分页查询个人用户主档。 |
| `POST /api/v1/personal-users` | `personal_user:write` | `CreatePersonalUserRequest` + `X-Idempotency-Key` | `ApiResponse<PersonalUserDetailVO>` | 渠道登录幂等创建主档；已存在则返回既有主档；渠道身份冲突返回 409。 |
| `GET /api/v1/personal-users/{personalUserId}` | `personal_user:read` | 路径参数 `personalUserId` | `ApiResponse<PersonalUserDetailVO>` | 查询单一主档；不存在返回 404。 |
| `PUT /api/v1/personal-users/{personalUserId}` | `personal_user:write` | `UpdatePersonalUserRequest`（含 `version`） | `ApiResponse<PersonalUserDetailVO>` | 编辑资料（如隐私同意版本）；`version` 乐观锁，冲突返回 409 `VERSION_CONFLICT`。 |
| `GET /api/v1/personal-users/{personalUserId}/conflicts` | `personal_user:read` | 路径参数 `personalUserId` | `ApiResponse<List<IdentityConflictCaseVO>>` | 查询该用户的渠道身份冲突案例列表。 |
| `PATCH /api/v1/identity-conflicts/{conflictCaseId}` | `personal_user:write` | `ResolveConflictRequest` | `ApiResponse<IdentityConflictCaseVO>` | 人工处置冲突（合并/阻断/驳回）；状态已终态时返回 409 状态冲突。 |

## 3. 关键请求与响应字段

| 模型/字段 | 类型 | 中文说明 | 约束 |
| --- | --- | --- | --- |
| `CreatePersonalUserRequest.channelType` | string | 渠道类型 | 必填；枚举 `wechat`/`alipay`。 |
| `CreatePersonalUserRequest.externalSubjectFingerprint` | string | 外部主体指纹 | 必填；由受控密钥服务生成；不得使用可被枚举的裸哈希。 |
| `CreatePersonalUserRequest.normalizedPhoneFingerprint` | string | 规范化手机号指纹 | L3 加密存储；仅经指纹索引查询。 |
| `UpdatePersonalUserRequest.version` | integer | 乐观锁版本 | 必填；冲突返回 `VERSION_CONFLICT`。 |
| `ResolveConflictRequest.resolution` | string | 处置结论 | 必填；枚举 `resolved_merge`/`resolved_block`/`rejected`。 |
| `PersonalUserDetailVO.externalSubjectFingerprintMasked` | string | 脱敏外部主体指纹 | 只读；明文永不回显。 |
| `PersonalUserDetailVO.normalizedPhoneFingerprintMasked` | string | 脱敏手机号指纹 | 只读；明文永不回显。 |
| 主档 `status` | string | 主档状态 | 枚举 `pending_verification`/`active`/`blocked`/`conflict`/`manual_review`；状态迁移以 W2 个人身份状态机为准。 |

## 4. 后端、前端与测试落地

- 后端目录为域包直挂 `customer/{controller,dto,vo,service,service/impl,mapper,entity,cache,util}`；渠道身份映射、冲突登记与处置在 `service` 编排，L3 指纹生成与脱敏工具在 `util`，Controller 不直连 Mapper。
- 前端目录按业务模块组织，如 `views/customer/personal-user/`；列表、详情、冲突处置页覆盖加载、空、失败、无权限、版本冲突与关闭态；所有敏感字段仅显示脱敏指纹。
- 测试按"渠道登录幂等创建、指纹不可枚举、L3 字段不回显、409 渠道身份冲突、编辑乐观锁冲突、冲突处置状态机（终态不可重复处置）、404 边界、两档权限"逐项覆盖；每个测试类、方法、夹具和关键 Given/When/Then 代码块写中文说明。
