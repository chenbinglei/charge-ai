# 充电运营平台 API 通用接口规范

> 版本：v1.0
> 状态：现役强制规范；W1 起所有 HTTP API 必须遵守。
> 依据：DEC-20260814-021、《[全栈研发工程规范](../standards/全栈研发工程规范-v1.md)》。
> 适用范围：P1、P2、M1–M4、D1 与所有后端服务的版本化 HTTP API。

## 1. 基本约定

- 路径采用 `/api/v{major}/{resource}`，资源名使用小写 kebab-case 复数；破坏性变更必须升大版本。
- JSON 字段使用 lowerCamelCase；所有请求、响应和字段在 OpenAPI 中必须有中文说明、类型、必填性、范围、枚举含义与脱敏规则。
- Controller 只接收请求 DTO、调用 Service、返回响应 VO；不得以 `Map`、持久化 Entity 或未声明的动态结构充当业务响应。
- 业务语义由 HTTP 状态码和统一响应体共同表达；前端不可只以 HTTP 200 判断操作成功。

## 2. 统一响应模型

所有正常、业务失败和系统失败的 JSON 响应均使用 `ApiResponse<T>`；网关无法到达上游、文件流下载等协议例外必须在 OpenAPI 中明确标注。

```json
{
  "code": "SUCCESS",
  "message": "操作成功",
  "data": {},
  "traceId": "018f...",
  "timestamp": "2026-08-17T00:00:00.000Z"
}
```

| 字段 | 类型 | 中文说明 | 规则 |
| --- | --- | --- | --- |
| `code` | string | 稳定业务结果码 | 成功固定为 `SUCCESS`；失败使用登记错误码，不能以异常文本代替。 |
| `message` | string | 面向调用方的中文结果说明 | 不含堆栈、SQL、凭据或敏感事实。 |
| `data` | object/null | 成功结果或失败时的受控补充信息 | 必须是已定义 VO、分页对象或 `null`，不得为随意 `Map`。 |
| `traceId` | string | 本次请求的全链路追踪标识 | 每次响应必返；可用于日志、告警和工单定位。 |
| `timestamp` | string | 服务端生成响应的 UTC 时间 | RFC 3339、毫秒精度。 |

列表 API 的 `data` 使用 `PageResponse<T>`：

```json
{
  "items": [],
  "pageNo": 1,
  "pageSize": 20,
  "total": 0
}
```

`pageNo` 从 1 开始；`pageSize` 必填并受接口上限约束；`total` 为满足过滤条件的总量。游标分页仅用于明确声明的高频流式查询，且必须说明游标有效期和排序字段。

## 3. 状态码、错误码与参数错误

| 场景 | HTTP 状态 | `code` 示例 | 规则 |
| --- | --- | --- | --- |
| 查询或操作成功 | 200 / 201 / 204 | `SUCCESS` | 201 用于创建；204 仅可用于无响应体的协议例外。 |
| 参数校验失败 | 400 | `VALIDATION_ERROR` | `data` 返回字段名、中文原因和受控约束，不泄露内部规则。 |
| 未登录或令牌无效 | 401 | `UNAUTHENTICATED` | 不返回账户是否存在。 |
| 无页面、数据或业务操作权限 | 403 | `FORBIDDEN` | 记录审计与 `traceId`。 |
| 资源不存在或不可见 | 404 | `RESOURCE_NOT_FOUND` | 不可用 404 探测其他租户数据。 |
| 幂等冲突、版本冲突、非法状态迁移 | 409 | `IDEMPOTENCY_CONFLICT` / `VERSION_CONFLICT` / `STATE_CONFLICT` | 必须说明可安全重试或人工处置方式。 |
| 业务规则不满足 | 422 | 模块稳定错误码 | 例如资格、余额、状态、额度不满足；不得滥用 500。 |
| 未预期系统错误 | 500 | `INTERNAL_ERROR` | 只返回中文通用提示，完整异常仅入脱敏日志。 |

错误码按 `<MODULE>_<SCENARIO>` 使用大写下划线，例如 `IAM_USER_USERNAME_DUPLICATED`；必须在模块 OpenAPI 和错误码说明中登记，发布后不得复用或改变原有语义。

## 4. 幂等、并发与审计

- 创建、扣款、退款、控制命令、监管报送与其他可能因重试产生副作用的写接口必须要求 `X-Idempotency-Key`；服务端按主体、接口、键和请求摘要保存结果，重复请求返回同一业务结果。
- 编辑与状态变更接口必须传 `version` 或同等并发控制字段；冲突返回 `VERSION_CONFLICT`，前端提示刷新后再操作。
- 所有写接口均记录操作主体、对象、结果、时间、关联 ID 与 `traceId`；禁止在响应、日志或审计中写入密钥、完整手机号、证件、支付卡或原始敏感报文。

## 5. 契约与前端使用规则

- 后端先更新根 `contracts/openapi/` 的版本化契约及中文字段说明，通过 API 自动化与人工验证后，前端才可调用。
- 前端 API 客户端统一解包 `ApiResponse<T>`：仅 `code == SUCCESS` 进入成功分支；失败按稳定 `code` 处理，展示 `message` 并保留 `traceId` 供支持人员定位。
- 请求 DTO、响应 VO、分页对象、错误码和幂等要求均须在 TypeScript 类型、Java 模型、测试和接口文档中保持同名同义；禁止前端自行拼装未登记字段。
