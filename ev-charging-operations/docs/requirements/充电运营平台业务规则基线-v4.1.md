# 充电运营平台业务规则基线

> 版本：v4.1（评审基线）

## 1. 权限与数据边界

1. 统一设备接入服务管理充电桩、电表等设备接入、协议/API/密钥、采集周期、原始遥测和标准化数据落库；可直接接入设备，也可接收 IOT 按统一协议同步的数据。设备数据存储为设备遥测优先权威来源，并向 P1 提供标准化设备数据及资产范围引用。
2. P1“系统与配置 → 权限管理”维护平台管理员、租户可授权范围和授权审计。平台管理员拥有全租户权限，并向租户分配可再授权的页面、功能和数据范围。
3. P1“客户与权益 → 合作运营 → 租户管理”由租户管理员维护本租户组织、角色、用户和租户内权限，并为其下属企业配置不超过租户范围的最大授权范围。
4. 企业管理员在 P2“企业管理 → 企业组织 → 企业组织管理”配置本企业组织、角色、成员账号、页面权限和数据范围；权限数据由平台统一权限中心保存、校验和审计，不得超出上级授权。
5. 当前不配置 M1、M2、M3、M4 的小程序页面/功能权限；M1 由平台统一开放，其他小程序按现有应用定位运行，后续另行扩展。
6. P1 仅向平台工作人员及获授权租户人员开放；企业客户、企业管理员和企业成员不得登录或被授予 P1 页面、功能、数据权限，企业业务管理统一在 P2 与 M4。
7. P1“系统与配置 → 应用与内容 → 小程序管理”维护 M1、M2、M3、M4 的应用档案、状态、版本发布、灰度/回滚和配置审计；其功能开关仅控制已批准能力的投放，不构成页面或角色权限。AppID、密钥、证书等敏感凭据由安全配置中心受控保管。
8. M3 具备平台工作空间和租户工作空间；每次切换均重新校验角色、数据范围、有效期和审计记录。租户工作空间不得查看平台商户、个人资金、企业资金及完整用户发票。

## 2. 资产与外部服务边界

1. 接入侧字段（设备标识、通信状态、能力、遥测、原始告警）在 P1 只读展示；P1 字段（经营属性、开放规则、服务资料、扩展业务字段、收益模型）由业务侧维护。设备数据可由统一设备接入服务直连采集或由 IOT 同步，但以设备数据存储为优先来源。
2. 自定义字段必须通过资产字段模板维护类型、校验、适用资产、权限、版本和审计；不得保存 API 密钥、证书、支付敏感信息。
3. 停车、道闸、车位闸机、厕所门禁等设备接入和控制协议归 IOT 或第三方设备平台；P1 维护业务映射、权益、记录、对账和异常。
4. 停车费用的收款、退款、发票由停车服务合法主体负责；P1 仅提供充电减免权益校验、核销、撤销和记录追溯。
5. “场站数据分析”以授权场站为边界，支持同时选择多个场站、多个统计数据点及时间范围，提供充电量、订单量、营收、利用率、功率、设备状态等按时/日/月粒度聚合的历史查询；每个“场站 × 统计数据点”组合对应一条曲线，选择多少组合即展示多少条曲线。指标定义、统计口径、时区、数据延迟和缺失区间必须随查询结果可见。
6. “设备数据分析”仅查询统一设备接入服务已标准化入库且用户有数据权限的功能点，支持同时选择多个设备和多个功能点；每个“设备 × 功能点”组合对应一条曲线，选择多少组合即展示多少条曲线。曲线和明细须保留采样时间、数据来源、质量标记及必要的聚合粒度；缺失、补采、插值数据不得伪装为原始遥测，且不得通过运营页面修改设备协议、功能点定义或原始值。

## 3. 个人用户身份与支付规则

1. M1 是面向公众的渠道中立个人充电产品，微信与支付宝小程序共享个人用户、订单、钱包、权益、发票和 V2G 业务事实。P1 不配置 M1 个人用户的页面或功能权限；小程序应用生命周期、内容、已批准业务开关和灰度投放不构成角色/页面授权。
2. M1 渠道登录成功时，服务端必须创建或更新个人用户主档及渠道身份映射。渠道身份以“渠道 + 应用实例 + 外部主体标识”唯一；经用户授权并验证的规范化手机号用于匹配既有个人用户。命中既有用户时幂等更新绑定和登录资料，未命中才创建个人用户，不能重复创建钱包、订单或权益事实。
3. 同一渠道身份已绑定其他个人用户、手机号命中人工锁定/冲突用户、授权资料不完整或身份解绑/重绑时，不得自动合并账户；须保留审计并进入人工处置。手机号变更、账户状态和渠道身份绑定均由平台在 P1「个人用户」运营流程统一管理，M1 不提供自助绑定、解绑或合并入口。
4. 授权码只能由服务端向渠道校验或换取，客户端提交的手机号不得直接信任；身份/会话接口必须覆盖会话失效、限流、防重放与审计。手机号、实名、支付与提现资料按最小必要收集，记录隐私告知/同意版本，执行加密脱敏、访问/导出审计及保留/删除规则。
5. M1 可用性按应用发布状态、渠道健康状态、已批准业务开关、场站营业/开放对象、用户业务资格依次判定，不以页面权限替代。公开访客只可浏览对公众开放且营业中的站点；应用停用或渠道故障须明确关闭能力及既有会话处置。
6. 未取得经验证手机号的访客可浏览公开场站信息，但不得启动交易、支付、退款、权益核销、申请发票或使用 V2G；上述限制是业务资格校验，不是 M1 页面权限配置。
7. M1 可使用平台钱包余额、微信支付、支付宝支付及已接入的其他渠道；用户不要求必须办理会员或绑定车辆。
8. 微信小程序的现金充值、外部直付及其退款使用平台微信商户；支付宝小程序的现金充值、外部直付及其退款使用平台支付宝商户。外部直付差额退款和现金充值退款均原路退回；钱包支付订单的退款先恢复其来源资金批次。外部支付意图须固化渠道、应用实例、商户引用与路由版本快照；历史外部退款只使用原支付路由，后续配置变更不得影响历史订单。
9. 个人钱包现金余额由充值资金批次组成；每个批次固化原支付交易、渠道、应用实例、商户引用/路由版本、实收金额、已消费/冻结/已退款及可退款余额。赠送金、红包、积分等非现金资产独立建账，不得作为现金退款来源；钱包扣款、释放和退款均须按确定分配规则关联具体资金批次。
10. 未消费现金充值退款只能按原资金批次的原支付商户与路由处理，只影响钱包、原商户和渠道对账，不产生租户结算调整。商户迁移后，新商户只承接新交易；旧商户停止新收款但保留历史交易查询、原路退款和对账能力及充足退款资金，直至历史可退款余额、处理中退款和对账差异清零或已有经批准的处置方案。
11. 以钱包支付的充电订单退款或补差，应先按原资金批次分配规则恢复钱包；以外部渠道直接支付的订单退款，必须由原商户原路退款。两类充电订单退款、补差或后续价格修正均须形成租户结算调整；未锁账单可重算，已锁定或已付款账单只能追加调整或追补记录，不得回写历史账单。
12. 启动前应校验本次可用余额/可预付金额；余额支付、预付、权益抵扣等形成冻结或预授权，以避免订单完成后余额不足。
13. “个人交易明细”只读展示个人单笔预付、个人充值、个人退款和原支付渠道结果；退款申请、审批与处理仍在“退款与补差”中完成，避免两个入口重复修改同一退款事实。

## 4. 企业资金、车辆与电卡规则

1. 企业资金账户由平台统一管理账务，企业拥有使用权；租户不管理、不能划拨、不能冻结、不能扣除企业资金。
2. 企业可充值；企业总预存余额可划拨并锁定至车辆分组或电卡分组。分组资金、卡余额和总预存余额不得重复可用。
3. 车辆分组是 VIN 鉴权、资金归集、额度、可用场站和固定单笔启动金额的控制单元。一辆车辆只能属于一个有效车辆分组。
4. 电卡分组是电卡余额、单笔金额、周期限额和可用站点的控制单元。一张卡只能属于一个有效电卡分组；单卡可绑定多个企业用户，企业用户可绑定多张卡。
5. 企业成员可对企业下所有车辆分组车辆充电；对非本人可见分组车辆的成功订单标记跨分组使用，M2 不展示该分组完整资金。
6. M2 使用 VIN 鉴权时，按 VIN 所属车辆分组固定单笔启动金额冻结；使用电卡时，按卡的单笔启动金额和可用卡余额校验并冻结。
7. 企业授信仅可用于企业扫码充电且设备无法获取 VIN 的“先充后付”路径。未开启先充后付或可用预存资金加授信不足时，不允许启动；电卡不得使用授信。
8. 订单结束后，若 VIN 能匹配企业车辆分组，按对应企业资金账户结算；VIN 缺失或不匹配时标记异常。如无法确定企业归属，订单为未结算异常订单，待人工配置后结算。
9. “企业充值明细”只记录企业总资金账户的充值、到账、失败和退款；车辆分组、电卡分组的资金划拨、冻结、扣款及其流水继续由企业资金账户管理。

## 4.1 计费与企业协议价规则

1. 企业协议价由 P1“计费与营销 → 计费管理 → 企业协议价”维护，是企业专属充电计费规则，不属于企业资金、营销权益或租户结算方案。
2. 每条协议价必须明确企业主体、可选的车辆分组或电卡分组、适用场站、充电电价/服务费、优先级、版本及生效失效时间；同一匹配范围与有效期内不得存在相同优先级的冲突规则。
3. 订单启动时，先按企业、车辆分组/电卡分组、场站和有效期匹配协议价；命中后固化规则标识、版本和价格快照。后续协议价变更不得重算已启动、已完成、异常待处理或已锁定结算订单。
4. 企业协议价确定订单应收计费；营销权益核销、企业资金扣款和租户结算仍按各自规则处理，并保留与协议价快照的可追溯关联。

## 4.2 购售电价与营销规则

1. 电网购电价、售电价由 P1“计费与营销 → 计费管理 → 购售电价”维护，支持尖峰平谷深分时单价、日期范围和场站绑定；仅用于经营分析，不下发至桩、不参与充电或放电订单的对用户计费。
2. 同一场站、同一购售电类型和同一时间段内不得存在重叠生效模板；经营分析可按当前有效模板及场站收益模型重新计算，不为购售电价建立订单价格快照。
3. 营销能力须覆盖活动介绍、新人有礼、邀新有礼、微信群领券、直发券活动、导入发券、充值活动、充值活动订单、充电有礼、场站活动、积分兑换、积分抽奖、精准营销和客情关怀；活动介绍作为已发布活动的前台落地页。
4. 营销配置、发布、执行和数据查看由“系统与配置 → 权限管理 → 营销权限”按活动类型、页面操作、场站范围、预算范围、审批权限和有效期授权；不得在菜单层面预设平台或租户的唯一归属。

## 5. 场站定时充电策略规则

1. 策略以场站、充电设备和枪口为目标，不再以企业、车辆、VIN、车辆分组、资金或额度作为执行对象；策略只可由平台管理员或获授权租户管理员配置、发布、修改、启停和查看全量执行记录，企业客户平台 P2 与 M4 不提供策略配置能力。
2. 策略支持每日、工作日、周末、自定义星期、跨日时段和有效期；工作日/周末以中国法定节假日及调休规则为准。每条策略必须明确目标场站/设备/枪口、计划执行时间、目标可充状态和冲突优先级。
3. 到策略执行时间，系统按授权范围、设备在线状态、设备能力、告警/安全状态及策略优先级校验目标设备后，下发启用或停用充电服务的控制指令；并发数、启动间隔、总功率为可选分批参数。
4. 策略默认仅改变设备后续可充状态，不强制中断正在进行的充电订单；如需中断在充订单，必须由独立的紧急停机或已授权远程操作流程执行，并保留完整审计。
5. 设备离线、不支持控制、状态不允许、告警拦截、控制超时或执行失败均需记录具体原因并告警；执行记录须保存目标设备、计划时间、实际时间、指令、结果和来源策略。

## 5.1 占位提醒规则

1. 场站在“场站与运维 → 场站服务 → 服务配置”维护充电完成后的未离场提醒时长；该配置仅用于提醒与人工处置，不生成占位订单、自动收费或违约处罚。
2. 充电订单完成后，超过场站提醒时长且对应枪口仍非空闲时，生成占位提醒。提醒至少展示订单号、桩枪编号、用户手机号和占用时长。
3. 平台或获授权租户人员可通过拨号入口人工联系用户；系统不记录电话通话结果。小程序提醒应经通知事件与渠道适配器投递，留存发送时间、状态、回执和频控记录；开发 Mock 投递记录不得替代生产渠道投递验收。
4. 接入侧上报对应枪口状态为空闲后，占位提醒自动结束；订单撤销、枪口归属异常等情况按异常状态保留处置记录。

## 6. 租户结算、支付渠道与发票规则

1. 平台个人收款渠道与平台向租户付款渠道分离。个人支付不因场站变化而切换至租户商户；场站绑定的是租户结算方案。
2. 一个场站任一时刻只允许一个生效场站结算方案。方案包含结算主体、租户收款账户、对公/银联/第三方结算渠道、分成、费率、税率、责任方和有效期。
3. 每笔订单启动时固化场站结算方案版本。个人、企业、电卡订单均按该快照参与平台对租户结算；付款来源、收款商户和个人充值资金批次均不决定租户结算账户。
4. 未消费个人现金充值退款不属于租户结算。充电订单退款、补差和后续差异修正必须关联原订单、结算方案快照和调整原因，生成租户结算调整；未锁账单可重算，已锁定或已付款账单只能追加调整、追补或追收记录，不得回写历史账单。
5. 平台月度生成租户结算账单，经对账、差异处理、锁单及租户来票校验后，按受控渠道付款并留存回单。对账须覆盖收款商户、个人钱包资金批次、充电订单和租户账单四个事实面。
6. 平台统一面向个人和企业充电用户开具充电发票；租户在平台结算后向平台开具结算/履约发票；平台服务费如有，应形成独立应收、发票和可审计净额结算。
7. 支付渠道与路由菜单只显示商户引用、状态、能力和对账健康度；API 密钥、证书和签名参数由安全配置中心保管并最小授权访问。配置写入后须由服务端执行不回显的连通/绑定校验，结果与版本进入审计；不得以“已保存”代替渠道可用。
8. M1、M4 的用户充电发票入口统一位于“我的 → 发票服务”，提供抬头、申请、开票记录、下载和红冲状态；订单页面仅保留订单、售后或对账上下文。M2 是企业员工/司机的充电执行端，不提供发票入口，企业充电发票由企业管理侧与平台对接；M3 租户工作空间不展示完整用户发票，仍遵守其数据边界。半自动开票的票据文件须经病毒扫描、授权访问和短时下载链接保护，并留存上传、复核、发送、下载与失败重试审计。

## 7. 收益分析规则

1. 收益分析支持平台、租户、场站三级下钻，并按查询日期范围组合设备数据存储中的计量读数、订单、购售电价模板及场站收益模型重新计算。
2. 正向电量取场站总表/变压器表的正向有功电能分时增量；汽车充电量取充电订单电量；汽车放电量取放电订单电量；反向电量取反向有功电能分时增量。损耗电量为“(正向电量 − 汽车充电量) + (汽车放电量 − 反向电量)”。
3. 充电收入取充电订单金额；充电购电成本取正向有功分时电量乘对应电网购电价；V2G 售电收入取反向有功分时电量乘对应电网售电价；V2G 购电成本取桩上报的放电订单金额。
4. 运营补贴取有效期内充电订单电量乘运营补贴单价；场地租金、运营成本和运维成本按各自有效期与查询区间的重叠天数，以“月成本 ÷ 30 × 天数”分摊。充电收益为充电收入减充电购电成本；放电收益为 V2G 售电收入减 V2G 购电成本；总收益为充电收益加运营补贴加放电收益减场地租金、运营成本和运维成本。
5. 净投资为设备总成本加施工总成本减固定建站补贴。累计收益为整站投运期间累计总收益；日均、月均、年均收益分别按投运天数、投运天数/30、投运天数/365折算；年化收益率为年均收益除以净投资；投资回收周期为净投资除以年均收益，单位为年。净投资或年均收益不适用时应明确展示为不可计算。

## 8. V2G 规则

1. V2G 设备资产仍在场站/设备档案维护；放电经营、订单、计费、结算、对账独立于充电业务。
2. 放电不能以负数充电订单、个人钱包余额、企业预存余额或电卡余额替代建模。
3. 放电授权、策略、价格、执行、计量、结算均应有独立审计与异常处理。
4. 本期 M1、M2 的“我的 → V2G 放电”默认显示“真实服务暂未开通”；仅允许经授权的模拟器/夹具建立明确标记为 `SIMULATED` 的会话、订单、计量和收益记录。模拟记录不得下发真实放电控制、不得影响设备状态、不得进入个人收益余额、对账、监管或财务账本。
5. 真实现场试点须由用户另行批准，并冻结设备/车辆/并网适配清单、受控场站、双向计量、停止与回退预案、现场 E2E、风险负责人和试点结束处置；未具备这些证据不得创建真实放电会话或订单。
6. 真实 V2G 启用后，收益才可按放电授权和订单结算主体快照结算至独立用户 V2G 收益余额；不得与 M1 充电钱包、M2 企业资金或电卡余额互相抵扣、划拨或展示为同一余额。提现申请、付款、回单和提现记录均为待定能力：首发入口显示“暂未开通”，不创建提现业务事实；后续启用须由用户批准独立的实名、风控、付款渠道与审计方案。

## 9. 监管规则

1. 支持多省市监管业务参数映射、报送、回执、漏推识别、补推和对账；该能力由现行 `ecosystem-service` 在 W10 达到内部就绪，真实目标接入另以 C3-R 生产 Go 验收。
2. 报送采用可追溯的待发送记录、状态机、重试和人工补推机制；不得因补推修改原始订单事实。
3. 监管协议实现、设备接入、密钥和网络通道由 IOT/安全体系管理，P1 仅维护监管业务档案和运行结果。
