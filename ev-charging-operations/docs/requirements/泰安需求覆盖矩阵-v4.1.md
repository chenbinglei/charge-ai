# 泰安项目需求覆盖矩阵

> 版本：v4.1（评审基线）  
> 说明：泰安需求是平台通用能力的重要输入，不作为平台功能上限。状态“覆盖”表示已进入当前菜单、功能或规则基线；“边界覆盖”表示保留业务闭环但技术接入归统一设备接入服务、IOT 或第三方；“待后续评审”不代表遗漏。

| 泰安需求类别 | 状态 | v4.1 落点 | 处理说明 |
|---|---|---|---|
| 平台经营总览、运营数据 | 覆盖 | P1 运营总览、数据分析、D1、M3/M4 数据 | 支持经营、订单、收入、资产和告警专题，以及平台/租户/场站三级收益分析；M3/M4 支持授权范围内的充电、功率等移动趋势查询。 |
| 运营商、企业、组织、用户、角色、数据权限 | 覆盖 | P1 客户与权益、系统与配置；P2 企业组织 | IOT 提供租户/资产基础范围，P1 统一企业用户及业务权限。 |
| 场站、设备、枪口、设备分组、状态监控 | 覆盖 | P1 场站与运维、设备管理；M3/M4 场站 | 统一设备接入服务直连或接收 IOT 同步的充电设备与计量设备数据；P1 维护业务资产和运营资料，M3/M4 展示授权场站和设备实时状况。 |
| 场站数据分析、设备数据分析 | 覆盖 | P1 场站与运维 → 场站数据分析、设备数据分析 | 支持多场站/多统计数据点、多个设备/多个功能点的组合曲线查询；每个选中组合展示一条曲线。设备数据存储为遥测优先来源，并显示采样质量、延迟与缺失。 |
| 场站总表、变压器表与损耗核算 | 覆盖 | P1 设备管理、数据分析 → 收益分析 | 计量设备按接入周期保存正反向分时读数，按订单电量计算损耗与经营数据。 |
| 自定义字段、场站/设备资产资料 | 覆盖 | 资产字段模板、场站档案、设备档案 | 使用模板化字段与审计，避免自由字段失控。 |
| 计费、价格、服务费、营销 | 覆盖 | P1 计费与营销、充电计费管理、企业协议价、购售电价 | 计费与财务结算分离；企业协议价按企业、车辆分组/电卡分组和场站形成专属计费快照；购售电价仅用于经营核算。 |
| 营销活动与权益运营 | 覆盖 | P1 营销活动、发券活动、充值活动、充电活动、积分活动、精准营销、营销权限 | 覆盖活动介绍、新人/邀新、社群领券、直发券活动/导入发券、充值、充电有礼、场站活动、积分兑换/抽奖、精准营销与客情关怀。 |
| 会员、卡券、红包、积分、充值 | 覆盖 | 个人用户、会员与权益、个人资金管理 | 个人用户不强制会员或车辆认证。 |
| 个人预付、充值、退款、支付渠道 | 覆盖 | 个人资金管理、退款与补差、支付渠道与路由 | 微信、支付宝及其他渠道由平台商户收款和原路退款。 |
| 企业客户、车辆、企业用户、电卡、账户 | 覆盖 | P1/P2 企业菜单、M2/M4 我的 | 用车辆分组和电卡分组替代车队概念；M4 将车辆、电卡归入“我的”进行授权范围内的轻量维护。 |
| 企业余额、额度、授信、先充后付 | 覆盖 | 企业资金账户、用车额度与授权 | 授信仅用于无 VIN 且企业开启先充后付的扫码路径；电卡不可使用授信。 |
| 企业订单异常、VIN 校验、人工结算 | 覆盖 | 充电订单、企业资金规则 | 无法确定企业归属时标记未结算异常订单，人工配置后结算。 |
| 对公、银联、第三方租户结算 | 覆盖 | 结算账户管理、场站结算方案、付款与回单 | 一个场站任一时刻仅一个生效结算方案。 |
| 平台代用户开票、租户向平台开票 | 覆盖 | 用户充电发票、租户来票管理、平台服务费发票 | 三类发票主体和方向分离。 |
| 停车场、海康停车减免 | 覆盖 | 停车服务协同、停车流程 | 停车支付和发票归停车服务方，平台完成充电减免权益协同。 |
| 道闸、车位闸机、扫码抬杆 | 边界覆盖 | 出入口与车位协同 | 业务映射、记录与异常在 P1；接入协议、控制与 API 在 IOT/第三方设备平台。 |
| 厕所门禁 | 边界覆盖 | 园区便民服务协同 | 维护权益、授权和记录；门禁连接与控制归 IOT/门禁平台。 |
| 云快充 1.6 等外部设备协议 | 边界覆盖 | IOT 平台，不纳入 P1 菜单 | P1 消费标准化设备、订单和能力数据。 |
| 省市监管接入、漏推、补推、对账 | 覆盖 | 监管业务档案、监管报送与补推、监管对账与异常 | 支持多省市业务参数和可追溯报送闭环。 |
| 工单、巡检、设备告警、远程日志 | 覆盖 | 告警管理、运维工单、远程操作记录 | 原始告警/设备日志由统一设备接入服务优先提供，IOT 可按统一协议同步；P1 管理运营处置。 |
| 充满未离场提醒 | 覆盖 | 场站服务 → 服务配置、交易与售后 → 占位提醒 | 按场站阈值生成提醒，支持拨号入口和小程序提醒；枪口空闲后自动结束，不产生自动占位收费。 |
| 场站定时充电策略 | 覆盖 | P1 场站与运维 → 场站定时充电策略 | 平台或获授权租户以场站、设备、枪口配置定时启用/停用策略；默认不强制中断进行中的充电订单。 |
| 合作方、伙伴账单、应用市场 | 部分覆盖 | 合作方管理、租户结算、应用内容配置 | 合作协议、业务授权和结算已覆盖；“应用市场”需确认是否作为插件生态能力进入下一阶段。 |
| 电池安全、热失控、保护策略 | 边界覆盖 | 设备档案、告警管理、资产与运维分析 | IOT/设备提供检测和控制，P1 做运营告警、工单和分析；具体算法与保护参数待 IOT 能力确认。 |
| V2G 放电 | 覆盖 | P1 V2G运营、场站/设备 V2G 属性、M1/M2 我的 → V2G 放电 | 放电运营、订单、计费、结算和对账独立建模；M1/M2 支持扫码放电、实时状态/数据、收益余额/明细及提现记录，收益账户独立于充电钱包、企业资金和电卡。 |

## 待下一阶段评审项

1. “应用市场”是否需要发展为可安装的生态插件能力，及其安全审核、计费和版本治理方式。
2. 停车场、门禁、道闸的第三方接口能力清单、数据责任和故障补偿机制。
3. 电池安全算法、设备保护参数和 IOT 上报字段的最终标准。
4. 私有化部署中支付渠道、发票主体、资金清结算主体的合同与合规实现方式。
