## 1. 平台定位与业务模式

### 1.1 平台是什么

充电运营平台是连接**平台运营方、租户（运营商）、企业客户、个人用户、监管机构**五方主体的充电场站运营与结算系统：

- **平台运营方**：统一收款（个人微信/支付宝走平台商户）、统一面向充电用户开票、按场站结算方案向租户月度结算、维护全平台权限与配置。
- **租户（运营商）**：拥有并运营自己的场站与设备，接受平台月度结算，管理自己名下企业客户。
- **企业客户**：以车辆分组/电卡分组为控制单元进行企业充电核算，预存资金由平台统一记账、企业拥有使用权。
- **个人用户**：M1 公众充电，不强制会员、不强制绑定车辆。
- **监管机构**：省市监管报送（W10 内部就绪，真实接入 C3-R 独立生产 Go）。

泰安需求是平台通用能力的重要输入，**不是功能上限**；v4.1 基线共 106 项菜单/入口（P1 73、P2 9、M1 5、M2 3、M3 5、M4 5、D1 6）为 12 周全功能交付范围。

### 1.2 双部署模式

| 模式 | 定义 | 对业务的影响 |
| --- | --- | --- |
| IOT 协同（`IOT_COLLABORATIVE`） | 平台与 IOT linkos 协同部署 | 平台管理员、权限/角色、租户、场站资产、设备资产由 IOT 通过 HTTP 推送，平台**只读**（写 API 返回 `DEPLOYMENT_MODE_READONLY` 403，前端写按钮隐藏）；支持 SSO 免登录（ticket 换会话） |
| 独立部署（`STANDALONE`） | 平台独立运行 | 平台管理员、权限、租户、场站/设备资产全部由平台自行维护，允许写操作；SSO 入口关闭 |

两种模式下，**企业数据、小程序配置、支付/结算渠道、个人用户等平台维护域不受部署模式影响**。模式部署时二选一，运行期不变；由 `/api/v1/auth/profile` 返回，前端据此控制写按钮显隐。

### 1.3 七端分工

| 端 | 形态 | 面向角色 | 菜单项数 | 一句话定位 |
| --- | --- | --- | --- | --- |

| P2 企业客户管理平台 | Web | 企业管理员＋企业普通用户 | 9 | 企业经营与核算中枢：组织、车辆电卡、资金额度、订单对账、发票 |

| M2 企业充电小程序 | 小程序 | 企业员工/司机 | 3 | 企业充电执行端：扫码、订单、本人分组额度/电卡 |

### 1.4 资金与结算模式（业务主干）

1. **个人侧**：平台微信/支付宝商户统一收款；钱包现金余额由**充值资金批次**构成（每笔固化原支付交易、渠道、商户引用、路由版本与可退款余额）；退款一律**原路**；赠送金/红包/积分独立建账，不作现金退款来源。
2. **企业侧**：企业总预存余额划拨锁定至车辆分组/电卡分组；授信仅限无 VIN「先充后付」扫码路径；租户不可管理或挪用企业资金。
3. **租户侧**：每站任一时刻仅一个生效**场站结算方案**；订单启动时固化方案快照，个人/企业/电卡订单均按快照参与结算；月度账单 → 对账 → 锁单 → 租户来票校验 → 受控渠道付款 → 回单。
4. **平台服务费**：独立应收、开票与净额结算，与租户来票方向隔离。
5. **对账四账**：收款商户、个人钱包资金批次、充电订单、租户账单四个事实面必须可对账。

## 2. 角色与权限体系（三级体系，2026-08-20 用户澄清）

### 2.1 三级层级总表（权威业务事实）

| 层级 | 角色构成 | 权限来源 | 站点资产 | 主要使用端 |
| --- | --- | --- | --- | --- |
| 一级·平台级 | **仅平台管理员**（＝IOT 所说超级管理员；平台级不存在普通用户角色） | 拥有并管理**所有权限** | 管理所有租户名下的**全部站点** | P1（M3 平台工作空间） |
| 二级·租户级 | 租户管理员＋租户普通用户 | 平台管理员**创建租户时授予**的平台权限子集，租户只能使用被授权的权限 | 拥有并管理**本租户名下**站点 | P1（M3 租户工作空间） |
| 三级·企业级 | 企业管理员＋企业普通用户 | 由**所属租户授予**（不得超出租户被授权范围，即"子集的子集"） | 经平台/租户**授权**管理归属该租户的站点 | P2、M2、M4 |

### 2.2 权限授予链（逐级子集）

```
平台管理员（全量权限）
   │ 创建租户时授权 → 租户可用权限（子集）
   │                    │ 租户向企业授予 → 企业可用权限（子集的子集）
   │                    │ 企业管理员在 P2 给本企业成员配置页面/数据权限（≤ 企业被授权范围）
   └ 平台管理员也可直接为租户/企业配置其组织架构、角色、用户、关联站点（代维护）
```

- 平台管理员在**租户管理**创建租户并授权；被授权「企业管理」页面的租户也可创建企业。
- 每一级的授权结果由平台统一权限中心保存、校验并审计（授权审计菜单呈现平台—租户—企业授权链、同步状态与差异）。

### 2.3 维护规则（谁能维护谁）

| 操作者 | 可维护范围 | 落点菜单 |
| --- | --- | --- |
| 平台管理员 | 平台管理员与全部权限管理；**可代维护**租户/企业的组织架构、角色、用户、关联站点 | 系统与配置 > 权限管理（平台管理员、租户权限分配、营销权限、授权审计）；客户与权益 > 合作运营 > 租户管理；客户与权益 > 企业客户 > 企业管理 |
| 租户管理员 | 本租户及下属企业（不超过自身被授权范围，为下属企业设定最大授权范围） | P1 租户管理内本租户范围 |
| 企业管理员 | 本企业组织、角色、成员账号、页面/数据权限（不超出上级授权） | P2 企业组织管理 |
| 租户/企业普通用户 | 仅业务操作，无下级维护权 | 各端业务页面 |

> 说明：业务规则基线 §1.3 已表述"租户管理员维护本租户"；本报告按 2026-08-20 用户澄清补全"平台管理员可在对应菜单**代维护**租户/企业详细信息"这一事实，两者不冲突，属补充明确。

### 2.4 各端角色准入边界

- P1 仅向平台工作人员及获授权租户人员开放；**企业客户（企业管理员/成员）不得登录 P1**，企业业务统一在 P2 与 M4。
- M3 双工作空间：平台空间与租户空间严格隔离，切换即重校验；租户工作空间不得查看平台商户、个人资金、企业资金及完整用户发票。
- M1 面向公众：**不配置页面/功能权限**，能否交易由登录、账户状态、支付/余额、实名、V2G 授权等**业务资格校验**决定；未验证手机号的访客只能浏览公开站点。
- P2 主要给企业级管理员和企业级下用户使用。

### 2.5 权限技术模型（对齐 IOT linkos）

- 两档权限：`resource:read`（页面入口＋查询）/ `resource:write`（全部写操作按钮）；GET 校验 read，POST/PUT/PATCH/DELETE 校验 write。
- 菜单可见性：叶子菜单绑定 `resource:read`；一/二级父级**自动推导**（存在任一可见叶子即显示，否则整棵隐藏）；菜单树由 `/api/v1/auth/profile` 的 `menus` 后端推导返回，前端仅渲染。
- 数据范围：站点级授权表（`iam_org_data_scope`/`iam_tenant_data_scope`），取代 all/tenant/org/self 四档。
- 平台超管角色（`is_super_admin=1`）自动拥有全部权限，无需逐项绑定。

### 3.1 P1 运营管理平台（10 个一级业务域，73 项）

#### 域 1：运营总览（2 项）
- **覆盖菜单**：运营概览、待办与预警。
- **业务定位**：平台经营/运营/风险指标汇总与跨业务待办入口；仅概览与钻取，不承载配置。
- **关键边界**：待办处理动作跳转对应业务菜单，不在总览内闭环。

#### 域 2：场站与运维（15 项，分三个子域）
- **资产管理（3）**：场站管理（业务资产/经营属性/收益模型/开放范围/扩展字段）、设备管理（充电设备＋计量设备，正反向分时读数）、资产字段模板（模板化扩展字段，禁承载密钥/协议/支付敏感信息）。
- **场站服务（5）**：服务配置（营业状态/时间/标签/占位提醒时长）、停车服务协同（充电减免权益，停车收款/退款/发票归停车服务方）、出入口与车位协同（道闸/车位映射，协议归 IOT/第三方）、园区便民服务协同（门禁权益授权）、场站定时充电策略（仅平台或获授权租户配置，默认不中断在充订单）。
- **运行维护（7）**：实时监控、场站数据分析（场站×数据点组合曲线）、设备数据分析（设备×功能点组合曲线）、设备协议追溯（平台级排障权限，原文脱敏＋二次审批）、告警管理、运维工单（与告警生命周期独立）、远程操作记录。
- **数据归属**：接入侧字段（协议/遥测/原始告警）只读展示，以设备数据存储为遥测优先权威来源；业务侧字段（经营属性/服务资料/收益模型）由平台/租户维护。

#### 域 3：客户与权益（8 项）
- **个人客户（2）**：个人用户（运营资料/车辆/订单/权益/账户摘要/行为记录，车辆绑定为可选）、会员与权益（会员非充电前置）。
- **企业客户（4）**：企业管理（企业资料/合同/组织/角色/成员账号/权限，P2 配置＋平台统一保存校验）、企业成员账户、企业车辆管理（车辆分组为核算控制单元，一车一有效分组）、企业电卡管理（电卡余额由企业预存划拨锁定）。
- **合作运营（2）**：租户管理（平台管理员授权范围分配；租户管理员维护本租户）、合作方管理（非租户类渠道合作）。

#### 域 4：交易与售后（4 项）
- **充电交易（2）**：充电订单（进行中/已完成/异常待处理/人工结算/订单调整，异常是订单状态不另建菜单）、占位提醒（超时未离场提醒，不自动收费）。
- **售后服务（2）**：退款与补差（单笔预付差额退款/充值退款/原路退款/补收）、客服与申诉（咨询/投诉/占位申诉/评价/回访/SLA）。

#### 域 5：计费与营销（10 项）
- **计费管理（3）**：充电计费管理（计费规则/服务费/时段价格/版本发布）、企业协议价（企业专属价，订单启动固化版本与价格快照）、购售电价（尖峰平谷深，仅经营核算，不下发至桩）。
- **营销权益（7）**：营销活动（落地页）、发券活动（新人/邀新/社群/直发/导入）、充值活动、充电活动、积分活动（兑换/抽奖）、精准营销（客群圈选/触达/效果）、优惠资产与核销（卡券/红包/积分统一资产）。
- **关键边界**：计费属业务规则配置，不属于财务结算；营销权限按活动类型/页面操作/场站范围/预算/审批/有效期单独授权（W2 授权模型、W9 业务权限）。

#### 域 6：资金与结算（12 项，分四个子域）
- **个人资金（2）**：个人资金管理（钱包/充值批次/预付冻结/退款/支付流水；平台仅记账，实际清结算走银行/持牌机构）、个人交易明细（只读）。
- **企业资金（2）**：企业资金账户（预存/授信/划拨/分组资金/冻结/扣款；租户不可挪用）、企业充值明细。
- **租户结算（4）**：结算账户管理（对公/银联/第三方）、场站结算方案（每站一个生效方案）、租户结算账单（月度/差异/调账/确认/锁单）、付款与回单（与账单审批分权）。
- **账务与票据（4）**：渠道与账务对账（多账对账，不直接改写已完成订单）、用户充电发票（平台统一开票主体）、租户来票管理（平台付款前置控制）、平台服务费发票。

#### 域 7：V2G 运营（5 项）
- 放电授权与策略、放电订单（独立于充电订单与钱包）、放电价格与计费（不复用充电计费）、放电结算与对账、放电监控与分析。
- 本期仅 `SIMULATED` 模拟闭环；真实试点与提现为独立批准事项。

#### 域 8：数据分析（3 项）
- 经营分析与报表（历史分析，不含实时监控）、收益分析（平台/租户/场站三级下钻，组合计量＋订单＋购售电价＋收益模型）、资产与运维分析（利用率/故障率/服务质量，含重卡/V2G 专题）。

#### 域 9：监管接入（3 项，W10 `ecosystem-service`）
- 监管业务档案（运营商/站点/设备/参数映射）、监管报送与补推（漏推识别＋人工补推，不改写订单事实）、监管对账与异常。真实接入为 C3-R 独立生产 Go。

#### 域 10：系统与配置（11 项）

## 5. 业务规则要点（铁律提炼）

### 5.1 资金铁律
1. 退款一律原路：外部支付按原商户原路退；钱包支付先恢复来源资金批次。
2. 钱包现金余额＝资金批次之和；非现金资产独立建账。
3. 未消费充值退款不影响租户结算；订单退款/补差必须生成租户结算调整。
4. 已锁定/已付款账单不得回写，只能追加调整/追补/追收。
5. 企业资金平台统一记账、企业拥有使用权、租户不可挪用。
6. 四账对账：收款商户/钱包资金批次/充电订单/租户账单。

### 5.2 计费铁律
1. 订单启动时固化三类快照：计费价格、企业协议价版本、场站结算方案。
2. 快照后规则变更不重算已启动/已完成/异常/已锁定订单。
3. 购售电价仅经营核算，不下发至桩、不参与用户计费。
4. 同场站同类型同时段购售电模板不得重叠；每站仅一个生效结算方案。

### 5.3 身份与权限铁律
1. 授权码仅服务端校验/换取；客户端手机号不信任。
2. 权限逐级子集授予（§2.2）；企业不登 P1；M1 无页面权限只有业务资格校验。
3. M1 身份绑定/解绑/合并仅由 P1 个人用户运营流程处理。

### 5.4 边界铁律
1. 设备协议/接入/原始遥测归统一设备接入服务（直连或 IOT 同步），P1 只读展示。
2. 停车/道闸/门禁的设备协议归 IOT/第三方，P1 只做业务映射/权益/记录/对账。
3. 敏感凭据（AppID 密钥/证书/签名参数）仅安全配置中心受控保管，页面只显引用与状态。
4. 监管/外部生态（虚拟电厂等）不占 106 项与 60 工作日，W12 后独立扩展。

### 5.5 数据与展示铁律
1. 设备数据存储为遥测优先权威来源；补采/插值不得伪装原始遥测。
2. 分析指标口径、时区、延迟、缺失区间随查询结果可见。
3. 金额分存储/元展示、电量 kWh 存储 3 位/展示 2 位、功率 2 位等按《全栈研发工程规范》§5.2 执行。
