# 充电运营平台场景与流程图集

> 版本：v4.1（评审基线）  
> 关联规则：`充电运营平台业务规则基线-v4.1.md`

## 1. 个人用户扫码、预付及原路退款

适用：M1 个人用户，不要求绑定车辆或办理会员。

```mermaid
flowchart TD
  A[用户扫码或输入桩码] --> B[选择枪口]
  B --> C{支付方式}
  C -->|钱包余额| D[校验可用余额并冻结]
  C -->|微信/支付宝等| E[平台对应商户预付]
  D --> F{设备启动成功?}
  E --> F
  F -->|否| G[解冻或原路退款]
  F -->|是| H[充电中]
  H --> I[设备完成订单上报]
  I --> J[按订单计费结算]
  J --> K{预付金额大于实付?}
  K -->|是| L[退回钱包或原支付渠道]
  K -->|否| M[形成完成订单]
  L --> M
```

异常：启动失败、订单漏报、结算金额异常、退款失败均进入订单异常/退款补差；退款渠道必须与原支付渠道一致。

## 2. 企业 VIN、电卡与无 VIN 充电

```mermaid
flowchart TD
  A[企业用户扫码/插枪/刷卡] --> B{电卡方式?}
  B -->|是| C[校验卡状态、卡余额、单笔额度、站点范围]
  C --> D[冻结电卡金额]
  B -->|否| E{设备可获取可信 VIN?}
  E -->|是| F[VIN 匹配企业车辆分组]
  F --> G[校验分组资金、额度、站点范围]
  G --> H[按分组固定金额冻结]
  E -->|否| I{企业已开启先充后付且预存+授信充足?}
  I -->|是| J[按企业默认单笔额度冻结/占用]
  I -->|否| K[拒绝启动]
  D --> L[下发启动]
  H --> L
  J --> L
  L --> M[设备完成订单上报]
  M --> N{VIN 可匹配企业车辆?}
  N -->|是| O[按企业资金结算并释放差额]
  N -->|否| P[标记异常订单并按企业资金扣款]
  P --> Q{可确定企业归属?}
  Q -->|否| R[未结算，人工配置后结算]
```

异常：VIN 缺失、VIN 不在企业车辆分组、资金/额度不足、电卡冻结失败、订单晚到均记录原因；不能确定企业归属的订单不自动转入租户结算。

## 3. 场站定时充电策略

适用：由平台或获授权租户预先配置的场站、设备或枪口策略。企业客户不在 P2 或 M4 配置策略。

```mermaid
flowchart TD
  A[到达策略执行时间] --> B[读取目标场站/设备/枪口]
  B --> C{在授权范围且设备在线、支持控制?}
  C -->|否| D[记录执行失败并告警]
  C -->|是| E{安全状态、告警和策略优先级允许?}
  E -->|否| D
  E -->|是| F[按可选分批规则下发启用/停用指令]
  F --> G[记录目标设备、计划/实际时间和执行结果]
  G --> H{存在后续计划?}
  H -->|是| A
  H -->|否| I[结束]
```

策略只改变设备后续可充状态，默认不停止进行中的充电订单；设备离线、不支持控制、告警拦截或控制超时均记录原因。中断在充订单须通过独立的紧急停机或获授权远程操作流程处理。

## 4. 平台对租户月度结算与付款

```mermaid
flowchart LR
  A[完成订单] --> B[固化场站结算方案快照]
  B --> C[生成月度待结算明细]
  C --> D[订单/支付/资金/结算多账对账]
  D --> E{存在差异?}
  E -->|是| F[差异处理或生成调账单]
  E -->|否| G[生成租户结算账单]
  F --> G
  G --> H[确认并锁单]
  H --> I[校验租户来票]
  I --> J[按场站方案绑定账户和渠道付款]
  J --> K[记录付款结果、回单、失败重试]
```

个人微信/支付宝收款、企业预存扣款、电卡扣款均不决定租户结算账户；订单只按启动时固化的场站结算方案参与结算。

## 5. 停车减免与出入口协同

```mermaid
flowchart TD
  A[用户完成符合条件的充电] --> B[计算停车减免权益]
  B --> C[生成权益凭证和有效期]
  C --> D[用户在停车服务方完成停车支付]
  D --> E[停车服务方请求权益校验]
  E --> F{权益有效且未核销?}
  F -->|是| G[返回减免金额并核销]
  F -->|否| H[返回不可用原因]
  G --> I[同步停车/出入口结果]
  I --> J[形成协同记录与对账记录]
```

停车服务方负责停车费支付、退款和停车发票；P1 不代替其收款，仅保留充电优惠与协同记录。

## 6. 监管报送、漏推与补推

```mermaid
flowchart TD
  A[订单/站点/设备业务事件] --> B[生成监管待报记录]
  B --> C[发送并记录报文版本]
  C --> D{收到有效回执?}
  D -->|是| E[标记成功]
  D -->|否| F[自动重试]
  F --> G{超过重试阈值?}
  G -->|否| C
  G -->|是| H[进入漏推待处理]
  H --> I[人工核验并补推]
  I --> J[回执与平台订单对账]
```

补推只补发监管记录，不改写原始订单；监管协议、签名和传输密钥不在 P1 页面维护。

## 7. V2G 放电订单

```mermaid
flowchart LR
  A[放电授权与策略] --> B[校验设备双向能力与授权]
  B --> C[下发放电执行]
  C --> D[接收放电计量与状态]
  D --> E[生成放电订单]
  E --> F[按放电价格计费]
  F --> G[放电收益结算与对账]
  G --> H[异常分析与审计]
```

放电订单、计量、收益和结算独立建模，不能以充电负金额、个人钱包或企业电卡余额替代。

## 8. M1/M2 用户 V2G 扫码放电与收益提现

适用：M1 或 M2 中已实名、具备有效 V2G 授权和可提现资格的用户。

```mermaid
flowchart TD
  A[我的 → V2G 放电 → 扫码] --> B[校验二维码、设备双向能力与授权]
  B --> C{安全状态、收益主体和资格均有效?}
  C -->|否| D[提示原因并记录失败]
  C -->|是| E[创建放电会话]
  E --> F[展示实时状态、放电量、功率和已确认收益]
  F --> G{放电结束或异常?}
  G -->|否| F
  G -->|是| H[生成独立放电订单]
  H --> I[结算收益并更新独立收益账户]
  I --> J[查看收益余额、收益明细]
  J --> K[发起提现]
  K --> L{实名、可提现余额和风控校验通过?}
  L -->|否| M[展示失败/退回原因]
  L -->|是| N[记录提现处理中、成功或失败状态]
```

放电订单、收益余额和提现记录均独立于充电订单、个人充电钱包、企业预存资金与电卡余额。实时数据异常、遥测延迟和控制失败需显式提示，不能用估算值覆盖设备上报事实。

## 9. 充满未离场占位提醒

```mermaid
flowchart TD
  A[充电订单完成] --> B[读取场站服务配置的提醒时长]
  B --> C{超过提醒时长且枪口仍非空闲?}
  C -->|否| D[不生成提醒]
  C -->|是| E[生成待提醒记录]
  E --> F[展示订单号、桩枪、手机号和占用时长]
  F --> G[人工拨号入口]
  F --> H[发送微信小程序提醒]
  H --> I[记录发送状态与回执]
  G --> J{接入侧上报枪口空闲?}
  I --> J
  J -->|是| K[自动结束提醒]
  J -->|否| F
```

占位提醒仅用于提醒与人工处置，不自动生成占位订单、收费或违约处罚；电话由人员自行拨打，系统不记录通话结果。

## 10. 场站收益与投资回收分析

```mermaid
flowchart LR
  A[设备数据存储\n正向/反向分时电量] --> B[按场站购售电价计算\n充电购电成本与V2G售电收入]
  C[业务数据存储\n充电/放电订单] --> D[读取订单金额与电量\n充电收入、V2G购电成本、运营补贴]
  E[场站收益模型\n投资、补贴、租金、运营/运维成本] --> F[按有效期分摊成本与净投资]
  B --> G[收益分析]
  D --> G
  F --> G
  G --> H[电量与损耗]
  G --> I[累计/日均/月均/年均收益]
  G --> J[年化收益率与投资回收周期]
```

购售电价、补贴和月度成本按查询日期范围的当前有效配置重新计算；充电订单金额与桩上报的放电订单金额不被后台购售电价改写。
