# Design

架构图、流程图、数据模型、状态机和技术决策资料的入口。

## 先读什么

此前本目录将多份不同受众、不同状态的文档全部列为“当前设计”，造成了服务边界和 Kafka 链路的阅读歧义。自 2026-08-13 起，按以下优先级阅读：

1. [架构基线与服务边界 v2](充电运营平台架构基线与服务边界-v2.md)：**唯一实施架构入口**，定义服务、数据所有权、同步/异步边界、支付退款与 WebSocket。
2. [事件协作与 Kafka 通俗说明](事件协作与Kafka通俗说明-v1.md)：先理解 Kafka、消费者组、Outbox、DLQ 与“该不该用 Kafka”。
3. [Kafka 事件目录与消费组清单](../../contracts/events/README.md)：**唯一事件入口**，定义 Topic、发布者、消费者组、分区键、重放和 DLQ。
4. [充电运营平台12周全功能交付实施计划 v3](../requirements/充电运营平台12周全功能交付实施计划-v3.md) 与 [业务规则基线 v4.1](../requirements/充电运营平台业务规则基线-v4.1.md)：定义业务范围、资金结算不变量和交付门禁。
5. [高风险契约与状态机 v1](高风险契约与状态机-v1.md)：设备控制、支付退款、双模式、监管任务及 C3-R 生产 Go 的冻结规则。

其余文档不得与上述三类入口竞争权威性；它们分别承担决策、选型、沟通或历史逻辑映射用途。
