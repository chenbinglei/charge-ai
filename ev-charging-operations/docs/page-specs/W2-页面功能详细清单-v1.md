### 0.1 权限码与按钮规则（两档模型）

- 权限模型为「资源 + 读/写两档」（`resource:read` / `resource:write`），与 IOT linkos 对齐；不再区分菜单/按钮/API 三级权限。
- 页面入口与查询按钮：校验 `resource:read`；拥有 `resource:read` 即可见该页面全部查询能力。
- 全部写操作按钮（新增/编辑/删除/导出/审批/启停/绑定等）：统一校验 `resource:write`，不再逐按钮设置权限码；拥有 `resource:write` 即显示该页面全部写操作按钮。
- 纯查看页面（如授权审计）只有 `resource:read`，无写按钮。
- API 鉴权：GET 接口校验 `resource:read`；POST/PUT/PATCH/DELETE 接口校验 `resource:write`。

### 0.1.1 菜单可见性规则（父级自动推导）

- 一级/二级菜单不单独设权限码：其下存在任意已授权（`resource:read`）的三级页面即显示；全部三级页面都无权限则该父级菜单整棵隐藏——不出现空菜单。
- 菜单树由后端 `GET /api/v1/auth/profile` 的 `menus` 返回（后端按权限推导），前端仅渲染返回的可见菜单，不自行推导。
- 前端路由守卫：访问不在 `menus` 中的路由时重定向 403 页。
- 菜单层级调整（如三级并入二级）仅改后端菜单配置与权限表 `menu_path` 映射，页面权限码不变；待前端骨架页确定后统一调整。

### 0.2 双模式交互规则（IOT 协同 / 独立部署）

- 平台部署模式（`deployment_mode`：`IOT_COLLABORATIVE` / `STANDALONE`）在部署时二选一，登录后由 `/api/v1/auth/profile` 返回，前端用于按钮显隐。
- **IOT 协同模式**：平台管理员、权限/角色/策略、租户、组织、站点级数据授权等 IOT 维护数据域的页面，新增/编辑/删除按钮一律隐藏（列表正常展示）；对应写 API 返回 `DEPLOYMENT_MODE_READONLY`(403)。
- **IOT 协同模式 SSO 免登录**：IOT 平台用户点击入口跳转 P1 前端 `/sso/login?ticket=xxx`，自动换会话直接进入平台（无登录页），仅识别已推送用户；ticket 失效展示失效页并提供返回 IOT 链接（详见《认证与SSO接口规范》§4）。
- **独立部署模式**：全部页面按权限正常读写；`/sso/login` 入口关闭。
- 两种模式下，企业数据、小程序配置、支付/结算渠道、个人用户等平台维护域不受模式影响。
- IOT 协同模式下改密入口隐藏（密码在 IOT 侧修改后推送新哈希）。
