# 充电运营平台全栈研发工程规范

> 版本：v1.3
> 状态：现役强制规范；全栈默认采用业务模块优先的传统分层。
> 适用：本项目的 Java 21 / Spring Boot / MyBatis-Plus、Vue 3、uni-app、MySQL、ClickHouse、Kafka、MQTT、运维和交付资产。
> 依据：DEC-20260814-019、DEC-20260814-020、DEC-20260814-021、DEC-20260814-022；以《[平台技术命名规范](平台技术命名规范-v1.md)》和现行实施计划为上位约束。

## 1. 使用方式与底线

本文件定义本项目的全栈默认实现方式：**业务模块优先的传统分层**。它从 W1 起是后端、前端、测试、契约、数据库和运维资产的强制结构；W0 已取消的空包冻结不恢复，也不追溯要求 W0 创建业务包。每个需求在编码前先确定：需求编号、服务与业务模块、OpenAPI/事件/MQTT 契约、数据拥有者、迁移、测试层级和前端入口；任何一项未确定，不得先写页面或业务代码。

- 注释、日志说明、异常信息、测试显示名称、提交说明和文档**必须使用中文优先**；协议原文、标准术语、类名、字段名、第三方 SDK 固有文本可保留英文。所有新增类、接口、枚举、方法、字段、请求/响应模型、实体字段、关键代码块和测试用例均须有准确的中文说明；仅语义显然的局部变量、导入和单行赋值可免于重复注释。
- 本规范对代码注释的要求优先于一般文档的“避免逐行注释”原则：必须写的是对外模型、状态、字段、方法和风险代码块的业务说明；禁止的是只把语法逐行翻译成中文的噪声注释。自动检查只验证“应有说明的位置未缺失”，准确性、脱敏和业务边界仍由评审门禁判断。
- 不允许为了凑目录而创建空 Controller、虚假 Entity、空 Mapper、空 API、空 Topic 或空迁移。
- 新业务按“契约和迁移 → 后端与 API 验证 → 前端 → E2E”串行推进；不得绕过现行模块门禁。

## 2. 项目目录与职责

```text
ev-charging-operations/
├── backend/
│   ├── services/                  # 七个可部署服务，服务间不直接 Maven 依赖
│   └── libraries/                 # shared-kernel、contracts、testkit
├── frontend/
│   ├── apps/                      # P1、P2、M1-M4、D1 七端
│   └── packages/                  # ui、design-tokens、types、api-client
├── contracts/                     # openapi、events、mqtt 的唯一事实来源
├── database/                      # 按拥有服务/schema 的 Flyway 与 ClickHouse 资产
├── tests/                         # 跨服务 unit、integration、contract、e2e、security、performance
├── platform/                      # 部署、可观测性、环境模板和 Runbook 对应资产
├── docs/                          # 需求、设计、规范、接口、集成资料
└── delivery/                      # 验收、执行证据、发布与部署记录
```

业务代码不得放进 `shared-kernel`；它只容纳无业务归属的错误模型、上下文、ID、时钟和幂等基础能力。共享前端包不得保存页面业务状态或绕过服务端权限。任何跨服务事实都通过版本化契约协作，禁止跨 Schema 写入。

## 3. 后端服务目录：业务模块优先的传统分层

每个服务以 `com.elink.evco.<service>` 为根包；启动类放根包，保证组件扫描覆盖全服务。业务实现必须先按模块聚合，再在模块内采用传统层次，避免全服务的 `controller.trade`、`controller.iam` 等横向大包。无自有持久化数据的网关不创建 `mapper` 或 `entity` 包。

```text
src/main/java/com/elink/evco/<service>/
├── <Service>Application.java       # 唯一启动类；不放业务逻辑
├── config/                         # Spring、鉴权、异常、OpenAPI 等全服务技术配置
├── common/                         # 仅服务内复用的错误码、响应、常量和基础能力
├── module/
│   └── iam/                        # 业务模块；其他模块同级，例如 trade、customer
│       ├── controller/             # HTTP/WebSocket 入站适配
│       ├── dto/                    # 请求、命令、分页条件等入参传输对象
│       ├── vo/                     # 面向调用方的响应对象；不得直接返回 Entity
│       ├── service/                # 用例接口、事务语义和业务编排
│       │   ├── impl/               # Service 的唯一实现位置
│       │   ├── policy/             # 高风险模块的可替换业务策略
│       │   ├── calculator/         # 金额、计量或结算的可测试计算器
│       │   ├── statemachine/       # 显式状态迁移与允许动作
│       │   └── validator/          # 跨字段、资格与不变量校验
│       ├── mapper/                 # MyBatis-Plus Mapper 和受控 SQL；仅访问本服务 Schema
│       ├── entity/                 # 持久化实体；一表一 Entity，不承担接口返回模型
│       ├── convert/                # Entity、DTO、VO 的显式转换器
│       ├── client/                 # 外部/其他服务的本地适配端口
│       ├── listener/               # 已批准事件或消息的入站监听
│       ├── job/                    # 已批准的定时任务
│       └── exception/              # 模块业务异常与稳定错误码
└── support/                        # 仅本服务技术辅助能力；跨服务能力放 shared-kernel
```

### 3.1 包职责与禁止依赖

| 包 | 可以做什么 | 禁止做什么 |
| --- | --- | --- |
| `controller` | 参数校验、认证主体获取、调用 Service、DTO/VO 映射、HTTP 状态码。 | 调 Mapper、写事务、写 SQL、实现业务规则、返回 Entity。 |
| `service` / `impl` | 用例编排、权限/数据范围、幂等、事务、状态迁移、调用 Mapper/Client。 | 依赖 Controller、Servlet、VO、其他服务实现。 |
| `mapper` | 单服务 Schema 的读写、分页与锁定 SQL。 | 业务判断、跨 Schema 写、拼接用户输入、`SELECT *`。 |
| `entity` | 表字段、审计字段、持久化映射。 | 接收 HTTP 请求、作为事件或 API 响应、携带 Controller 注解。 |
| `dto` | 入参和服务命令的数据表达。 | 持久化注解、敏感字段默认回显、业务计算。 |
| `vo` | 稳定且脱敏的响应模型。 | 写库、被 Mapper 返回、暴露内部审计/密钥/完整敏感信息。 |
| `convert` | 显式完成 Entity/DTO/VO 转换。 | 偷偷填充业务状态、绕过 Service 校验。 |
| `config` / `exception` | 技术配置、统一错误外观、拦截器。 | 放业务用例或业务规则。 |

允许方向是 `module.<name>.controller → service → mapper/entity`，`controller → dto/vo/convert`，`service → dto/entity/mapper/convert/client`。Mapper 只依赖 Entity 和技术框架；VO 不进入 Service/Mapper。不同模块不得直接引用对方 Mapper 或 Entity；确有协作时通过本服务 Service 或明确的 Client/事件契约。架构测试至少阻止 Controller 直连 Mapper/Entity、Service 依赖 Controller/VO、Mapper 依赖 Controller/Service/DTO/VO，以及跨模块 Mapper/Entity 依赖。

### 3.2 类、文件和命名

| 类型 | 固定格式 | 示例 |
| --- | --- | --- |
| Controller | `<资源>Controller` | `ChargingOrderController` |
| Service | `<资源>Service` / `<资源>ServiceImpl` | `ChargingOrderService` |
| Mapper | `<资源>Mapper` | `ChargingOrderMapper` |
| 持久化实体 | `<资源>Entity` | `ChargingOrderEntity` |
| 请求 DTO | `<动作><资源>Request` | `CreateChargingOrderRequest` |
| 服务 DTO | `<动作><资源>DTO` | `CreateChargingOrderDTO` |
| 响应 VO | `<资源>VO` / `<资源>DetailVO` | `ChargingOrderDetailVO` |
| 转换器 | `<资源>Convert` | `ChargingOrderConvert` |
| 异常 | `<资源>Exception` | `ChargingOrderException` |

一个 Java 文件只放一个顶级 `public` 类型。类名、方法、变量用英文技术名；数据库/API 字段遵循《平台技术命名规范》。布尔方法用 `is/has/can`，查询用 `get/list/page`，创建用 `create`，状态变更用准确动作如 `cancel`、`confirm`，不得滥用 `handle`、`process`、`data`、`util`、`common`。

### 3.3 编码模板

以下是未来有契约和迁移后才可使用的形态，不是 W0 业务代码：

```java
/**
 * 创建充电订单入口。
 *
 * <p>订单金额、用户资格和幂等判断由服务层完成；控制器不直接访问数据库。</p>
 */
@RestController
@RequestMapping("/api/v1/charging-orders")
class ChargingOrderController {
    private final ChargingOrderService chargingOrderService;

    @PostMapping
    ChargingOrderVO create(@Valid @RequestBody CreateChargingOrderRequest request) {
        return chargingOrderService.create(ChargingOrderConvert.toDTO(request));
    }
}

public interface ChargingOrderService {
    ChargingOrderVO create(CreateChargingOrderDTO command);
}

@Service
class ChargingOrderServiceImpl implements ChargingOrderService {
    /**
     * 在同一幂等键下只创建一个订单；事务边界覆盖订单与 Outbox 事实，不能只靠前端防重。
     */
    @Transactional
    public ChargingOrderVO create(CreateChargingOrderDTO command) { /* 省略业务实现 */ }
}
```

`@Transactional` 只允许在 Service 实现的公开用例方法上声明；异常必须包含稳定错误码、用户可读中文提示和可审计关联 ID。日志采用结构化字段并携带 `traceId`，绝不记录凭据、完整手机号、证件、支付数据或原始敏感报文。

## 4. 注释、格式与代码质量

- 类、接口、枚举、公共方法、字段、请求 DTO、响应 VO、Entity 与每个字段都必须写中文 Javadoc 或等效中文注释，说明业务含义、输入输出、必填/范围、脱敏、持久化或失败语义；状态机、资金/计量计算、权限/数据范围、事务/幂等、补偿、外部适配器必须同时说明不变量与风险边界。
- 复杂条件、循环、并发控制、异常转换、SQL、缓存键、前端分支和测试夹具必须在代码块前说明中文意图；禁止为逐行语法翻译添加噪声注释。
- TODO 格式固定为 `TODO(责任人/需求编号): 原因和截止条件`；没有需求编号或处置时间的 TODO 不得合入。
- 禁止 `@SuppressWarnings`、空 `catch`、魔法数、无边界分页、宽泛 `Exception`、`System.out`、裸字符串错误码和复制粘贴转换逻辑；例外须在评审记录说明。
- Java 使用 4 空格、UTF-8、LF、单行不超过 120 字符；前端使用 2 空格。提交前执行格式化、静态分析、单元测试和 `git diff --check`。
- 新增依赖必须说明用途、许可证、漏洞和替代方案；不得为了一个小功能引入大型框架。

## 5. 前端目录、UI 与调用边界

P1/P2/D1 采用 Vue 3；M1-M4 采用 uni-app。页面只属于各自 App；跨端复用设计令牌、无业务 UI 和 API 类型，不复制业务规则。

```text
frontend/apps/<app>/src/
├── app/                           # App 启动、路由/页面注册、全局布局和端内配置
├── modules/
│   └── iam/user/                  # 业务模块/功能；不得把业务代码分散到 src 根技术目录
│       ├── api/                   # 仅调用生成的 API Client
│       ├── components/            # 仅本功能复用的展示与交互组件
│       ├── composables/ constants/ stores/ types/
│       ├── views/                 # Web 页面，或由小程序薄页面入口引用的业务视图
│       └── __tests__/             # 单元和组件测试
├── shared/                        # 无业务归属的组件、组合式函数、工具、类型和样式
├── static/ styles/
└── App.vue main.ts                # 小程序另有 pages.json、manifest.json；pages/ 仅保留薄入口

frontend/packages/
├── api-client/                    # 由 OpenAPI 生成或受控封装
├── design-tokens/                 # 颜色、字型、间距、圆角、阴影、断点
├── types/                         # 契约共享类型，不能重复定义后端事实
└── ui/                            # 无业务归属的可访问组件
```

- `app/` 只负责启动、路由/页面注册、全局布局和端内配置；Web 路由直接指向 `modules/<module>/<feature>/views/`，小程序 `pages/<module>/<feature>/index.vue` 只负责框架页面注册并引用同模块视图。业务代码不得新建根级 `api/`、`views/`、`stores/` 或 `common/` 大包；历史资料中的 `frontend/common` 不是现役路径。
- `views/pages` 只负责页面组合；`components` 不直接调用 API；`api` 只调用生成客户端；`stores` 不保存密钥或替代服务端权限。跨端复用仅进入 `frontend/packages/` 或 `shared/`，且不得携带某一端的页面、租户规则或业务状态。
- Vue/TypeScript 的组件、props、emits、接口字段、组合式函数、store、接口封装、关键模板分支和异常处理均须有中文注释；页面注释说明业务入口、权限/数据范围和状态边界。
- 文件采用 kebab-case，Vue 组件使用 PascalCase；组件名、props、事件、状态、接口均有明确业务名。
- 每页必须实现 loading、empty、error、无权限、关闭态和网络降级；实时页面显示最后更新时间与重连状态。
- 视觉值只来自 `design-tokens`，不在页面散落颜色/间距魔法数；交互需具备键盘可达、焦点、标签和足够对比度。
- API 先经 OpenAPI 契约冻结，再生成客户端；不得手写重复接口、直接访问数据库、把权限判断只放在前端。

## 6. UI、需求与接口协作

每个功能卡片至少关联：菜单/场景编号、原型或状态说明、权限/数据范围、API 契约、异常文案、测试用例。UI 评审以“主流程、加载、空、失败、越权、禁用、移动端/桌面端”逐项截图留证。

REST 只使用版本化资源路径；请求 DTO 与响应 VO 的字段需在 OpenAPI 中有中文说明、必填/范围/枚举/脱敏规则。统一信封、分页、错误码、追踪与幂等规则以《[API 通用接口规范](../api/API通用接口规范-v1.md)》为准；破坏性变更升 API 大版本；事件/MQTT 先登记在根 `contracts/`，不得从 Java 类反推契约。

## 7. 数据库、MyBatis 与迁移

```text
database/
├── mysql/evco_<domain>/migration/VyyyyMMddHHmm__description.sql
└── clickhouse/evco_telemetry/{ddl,materialized-views,backup-restore}/
```

- 一个 Schema 只由其拥有服务迁移和写入；Flyway 仅新增前向迁移，已执行文件绝不修改。
- 每表必须明确主键、审计列、唯一约束、索引、数据分类、留存/删除策略；金额使用最小货币单位整数，时间 UTC，禁止以浮点处理金额或电量。
- Entity 对应本服务表，字段名与列映射明确；Mapper 的查询必须有数据范围、排序和分页上限，更新/删除必须有条件与受影响行数预期。
- SQL 禁止 `SELECT *`、拼接用户输入、无条件更新/删除、跨 Schema 写入。复杂 SQL 放 Mapper XML 或注解旁，必须有中文业务说明和执行计划验证。

## 8. 测试、配置与运维

| 类型 | 位置与要求 |
| --- | --- |
| 单元测试 | Java 测试与源码包镜像放在 `src/test/java/.../module/<module>/`；前端测试就近放在 `modules/<module>/<feature>/__tests__/`。覆盖 Service、转换、状态机、金额、权限、异常；测试类、方法、夹具字段、断言分组和关键准备/执行/验证代码块均有中文说明，显示名称描述行为与结果。 |
| 架构测试 | Java 放在 `src/test/java/.../architecture/`，校验服务 Maven 隔离、业务模块优先传统分层和跨模块禁止依赖。 |
| 集成测试 | Java 放在对应模块的 `integration/` 包并以 `IT` 结尾；覆盖 Mapper、迁移、事务、缓存、外部适配器，优先 Testcontainers 与脱敏夹具。 |
| 契约测试 | 根 `tests/contract/{openapi,events,mqtt}/`；校验 OpenAPI、事件、MQTT Schema 与生成客户端兼容性。 |
| E2E | 根 `tests/e2e/<app>/<module>/`；只能在 API 自动化与人工门禁通过后覆盖主流程、幂等、越权、失败/补偿和跨端路径。 |
| 性能/安全/恢复 | 根 `tests/{performance,security}/` 与对应 Runbook；按阶段覆盖目标负载、鉴权、故障、备份恢复，Mock 不得替代真实门禁。 |

配置按默认值、非敏感环境覆盖、受控密钥引用分层。仓库只能提交示例键和占位值；每项外部依赖要有超时、重试/退避、幂等、限流/熔断或明确关闭态。所有服务传播 `traceId`，健康检查不泄露内网地址或敏感信息，指标/告警/Runbook 用业务风险命名。

### 8.1 W1 必须落地的质量门禁

W1 的 CI 平台固定为 GitHub Actions，与现行 GitHub 仓库和 Pull Request 流程一致；在工具尚未实际接入前，只能写为“计划门禁”，不得宣称已经启用。每个 Pull Request 至少执行下列检查，任一失败不得合入：

| 范围 | 自动门禁 | 评审门禁 |
| --- | --- | --- |
| Java | Maven Java 21、Spotless 格式化、Checkstyle、ArchUnit、Surefire/Failsafe、JaCoCo；Mockito 必须使用显式 agent 配置或移除对 inline mock maker 的依赖，禁止依赖 JDK 动态挂载 agent。 | 中文 Javadoc/注释的业务准确性、事务、权限、脱敏和异常语义。 |
| 前端 | pnpm、ESLint、Prettier、`vue-tsc`、Vitest；API Client 与 OpenAPI 生成物一致。 | 模块归属、中文注释、页面全状态、可访问性和前端不替代服务端权限。 |
| 契约/数据库 | OpenAPI 与事件/MQTT Schema lint、Flyway 命名及前向迁移校验。 | 字段中文说明、数据分类、兼容性、幂等和失败处置。 |
| 仓库 | Markdown 本地链接、`git diff --check`、敏感文件扫描。 | 无无主 TODO、无过期现役表述、交付证据与变更影响同步。 |

注释缺失检查使用受控脚本只定位缺少中文说明的公开类型、公共方法、模型字段、测试显示名称和关键风险标记；它不能判断注释是否正确，不能以“脚本通过”替代人工审查。

## 9. 合入检查清单

- [ ] 需求、数据拥有者、契约、迁移、错误码和验收条件均已关联。
