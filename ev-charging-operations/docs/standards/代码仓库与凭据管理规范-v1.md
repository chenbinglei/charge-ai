## 2. 分支、提交与发布规范

| 项目 | 规则 |

## 3. Git/SVN 一致性与回滚

- Git 是模块级审查与发布的权威历史；SVN 是每项已完成变更的立即备份历史。两者均管理同一项目树，唯一例外是 `.git/`、`.svn/` 和明确忽略的本地文件。
- 每次开始工作先检查 Git/SVN 状态，并先更新 SVN 工作副本；完成一项功能、配置、测试或文档改动并通过对应验证后，必须立即以最小范围提交 SVN。模块通过全部门禁后，才可将同一组已提交 SVN 变更聚合为一个 Git Conventional Commit。
- 每次提交前分别检查 `git diff`/`git status` 或 `svn diff`/`svn status`，确认范围、测试结果和敏感文件。Git 与 SVN 的提交说明应能相互定位；需留存交付证据时，记录 Git commit 与覆盖的 SVN revision。
- 不得使用重写历史或远端强制覆盖保持一致。已提交的错误改动通过新的 Git revert、SVN 反向合并或 SVN revert 后的新提交恢复，并记录原因、涉及 revision、验证与结果。
- `.svn/` 必须由 Git 忽略，`.git/` 必须由 SVN 忽略；任何一侧发现对方行政目录或凭据、环境文件、证书、私钥、日志、构建产物的待提交项，均须先排除并复核。

## 4. 凭据分类与唯一保管位置

| 凭据类别 | 示例 | 实际值保管位置 | 仓库中允许出现的内容 |
| --- | --- | --- | --- |
| GitHub 身份凭据 | PAT、OAuth、SSH 私钥 | 开发机操作系统钥匙串 / 公司密码库；CI 使用 GitHub Actions Secrets。 | 仓库 URL、账号/权限用途、轮换状态；不得有 token。 |
| 支付与银行 | 微信/支付宝/银联/银盛/对公 API 密钥、商户证书 | 公司密码库或生产 Secret Manager；部署时注入。 | 渠道编码、商户引用 ID（脱敏）、密钥引用名、测试/生产状态。 |
| IOT 与 MQTT | 客户端密钥、CA 证书、设备签名密钥 | IOT 凭据系统或 Secret Manager。 | 协议版本、凭据引用名、轮换策略；不得有设备秘密或生产 Topic 地址。 |
| 数据库与中间件 | MySQL、Redis、Kafka、EMQX、MinIO 密码/证书 | Secret Manager 或客户部署的受控密钥文件。 | 脱敏环境变量名和 `.example` 模板。 |
| 第三方集成 | 监管、门禁、道闸、停车、开票 API 密钥/证书 | 公司密码库或对应部署环境 Secret Manager。 | 接口版本、连接器状态、凭据引用名和联系人。 |

生产、测试与开发凭据必须分离；任何凭据都不得通过聊天、邮件正文、Issue、PR 评论、截图或源代码传递。

## 5. 凭据台账（只登记元数据）

凭据实际值位于受控保管系统；本项目只维护以下台账字段。具体台账可存放在公司密码库、工单系统或受访问控制的表格中，**不得**将真实值、完整连接串或证书复制进仓库。

| 字段 | 说明 |
| --- | --- |
| `credential_id` | 稳定标识，例如 `github-project-publish-token`。 |
| `system` | GitHub、微信支付、IOT、监管等系统名称。 |
| `environment` | `development`、`test`、`production`。 |
| `owner` | 负责申请、使用和轮换的岗位/人员。 |
| `storage_reference` | 密码库/Secret Manager 中的引用路径或条目名；不得包含值。 |
| `scope` | 最小权限范围，例如仅仓库写入、仅测试商户退款。 |
| `created_at` / `expires_at` | 创建和到期日期。 |
| `last_rotated_at` | 上次轮换日期。 |
| `status` | `active`、`rotating`、`revoked`、`expired`。 |
| `incident_reference` | 如有泄露或轮换，记录工单/事件编号；不得记录 secret。 |

## 6. 泄露、轮换与权限原则

1. 一旦令牌、密码、私钥或证书出现在聊天记录、Git 历史、日志、终端输出、Issue 或 PR，立即视为泄露：先撤销/轮换，再排查使用范围。
2. 已泄露值不可继续作为“项目记忆”或临时凭据使用；在台账中将旧条目标为 `revoked`，登记新引用与轮换时间。
3. GitHub 令牌遵循最小权限、最短有效期和按人/自动化身份分离；CI 不复用个人令牌。
4. 每月核对一次活跃凭据的负责人、有效期和权限；人员离岗、合作结束或环境下线时立即撤销。
5. `.gitignore` 必须持续忽略 `.env`、证书和私钥文件；提交前使用 `git diff --cached` 与敏感文件扫描复核。

## 7. 本项目当前执行约定

- 本地 Git 推送使用已认证的 `gh` 与操作系统钥匙串，不在脚本或 Git 配置中保存个人访问令牌。
- 当前仓库为公开仓库。任何提交前必须确认不含客户数据、真实设备地址、支付商户资料、证书、Token 或未脱敏日志。
- 本文档仅规范管理方式，不授权创建、读取、分发或更改任何生产凭据；实际凭据操作须由其所有者在受控系统中完成。
