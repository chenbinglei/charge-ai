## 固定约束

- 范围为 v4.1 全部 106 个菜单/入口；国内省市监管由现行第七服务 `ecosystem-service` 在 W10 达到内部就绪，真实目标接入另以 C3-R 生产 Go 验收；不得自动删除功能或跳过测试。
- 模块严格执行后端/迁移/契约 → API 测试 → 前端 → E2E → 完成记录。
- W2 的 M1 渠道登录必须创建或更新统一个人用户主档；P1 不配置 M1 个人用户的页面或功能权限。W6 交付 P1 个人用户 360°运营视图。
- 外部资料未到位时，Mock 仅用于内部开发/API/E2E；微信真实登录、支付、结果通知和原路退款必须在生产 Go 前完成真实 E2E。V2G 首发结算至独立用户收益余额，提现保持待定关闭。
- 商户迁移不改变租户结算归属：旧商户保留历史退款/对账，新商户承接新交易；未消费充值退款不进租户结算，订单退款/补差以调整单处理，锁单或付款后不改写账单。
- 国内省市监管是现行 `ecosystem-service` 的 W10 内部就绪范围，需建立 Schema、Topic、消费者、P1 页面和可靠上报闭环；真实目标接入另以 C3-R 生产 Go。`integration-service` 不承担监管。仅虚拟电厂及其他第三方数据/调控属于 W12 后扩展，不得提前创建其 Topic 或消费者。
- 已验收模块变更、延期、加班、新增功能和外部渠道真实启用均须先在审批日志取得用户批准。
- SVN 仅在公司内网可用：外网完成的变更必须在 `05-SVN待同步清单.md` 逐项登记、保留测试和中文提交说明，并在回到公司内网后的首个工作会话优先补提。待同步项未取得实际 SVN revision 前不得将模块或发布标记为完全完成。
- 每周更新实际日期预测、阻塞、外部依赖、P0/P1 缺陷和下一模块解锁状态。
